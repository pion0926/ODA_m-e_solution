# 일반 업로드 병렬 분석

개발 문서 작업자는 `ThreadPoolExecutor`로 일반 업로드를 최대 4건 동시에 처리한다. `WORKER_CONCURRENCY`는 1~4로 설정하며 기본값은 4다. API와 작업자에 같은 환경변수를 전달한다. 업로드 HTTP 요청은 기존처럼 파일을 안전하게 접수하며, 백그라운드 추출·사전 판단·분석·매칭이 병렬 실행된다.

- 각 스레드 안에서 프로젝트·계정 컨텍스트를 설정하고 실행 시작 시 최신 연결 모델을 선택한다.
- DB의 `FOR UPDATE SKIP LOCKED`, 실행 토큰 검사 및 실행 중 문서 제외로 중복 처리를 방지한다. 30초마다 실행 토큰이 일치하는 문서의 임대를 갱신한다.
- 일반 문서는 문서별 분석·매핑을 별도로 저장한다. 최종 저장의 프로젝트 잠금은 짧은 트랜잭션에만 적용한다.
- 큐에서 사업계획서/PDM에 도달하면 앞선 일반 작업이 끝날 때까지 새 접수를 멈춘다. 기준 문서와 그 후속 사업 구성 갱신이 끝난 뒤 일반 병렬 처리를 재개한다. 현재 구성은 작업자 인스턴스 하나를 전제로 한다.
- 사용자 중지·재요청, 처리 방식 선택 대기, 실패 재시도는 기존 실행 토큰 보호를 따른다.
- 종료 신호를 받으면 새 접수를 중단하고 실행 중 작업을 마무리한다. 컨테이너가 강제 종료되면 임대 만료 후 새 실행 토큰으로 복구한다.

`tools/qa_intake_controls.py`는 임시 DB에서 4개 스레드 동시 진입, 서로 다른 계정·프로젝트·모델 격리, 중복 실행 방지와 기준 문서 단독 실행을 검증한다. 외부 AI 호출은 테스트 응답으로 대체한다.
