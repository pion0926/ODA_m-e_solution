# 실제 자료 DAC 입력 한도 오류 수정 및 재검증

## 재현과 원인

- 개발서버 8002, codex 프로젝트 `743ab693-766d-4b75-bc84-60392edba4e0`, 원본 61개, `openai/gpt-5.6-luna` 유지.
- 최초 DAC 실행은 약 55분 뒤 응답 본문의 오류 400에서 중단했다. HTTP 상태는 200이어서 기존 HTTP 오류 분류를 지나쳤고 상세 메시지도 버렸다.
- 응답 오류 처리를 통일한 뒤 같은 자료로 재실행하여 공급자 원인을 확인했다: `Your input exceeds the context window of this model.`
- 효과성 첫 질문의 근거는 1,316건, 원본 레지스트리 직렬화 약 2,264,688자. 필수 목표·실적 표는 18개 행이었다. 효과성 두 번째 질문은 549건/924,209자, 세 번째는 252건/432,642자였다.
- 첫 복구 실행에서는 완료 원문 61개와 질문 4개를 재사용했고, 입력 한도가 발생한 첫 질문 외 나머지 질문을 진행하여 10개 체크포인트를 보존했다.

## 변경

1. HTTP 오류와 HTTP 200 안의 오류를 동일하게 분류한다. 입력 한도는 범위 축소 경로로, 명시적인 스키마 호환성 거절은 JSON 모드로 복구하고 로컬 검증은 유지한다. 인증·설정·결제 오류는 무작정 생성 재시도로 돌리지 않는다. 정제한 공급자 상세 원인을 보존하고 키/Authorization 형태는 마스킹한다.
2. 실패 실행의 확대 범위를 원문 검토 전에 복원한다. 좁은 초기 범위를 먼저 실행하여 완료된 확대 캐시를 덮어쓰는 문제를 막았다. 새 확대 결정도 요청 전에 저장한다.
3. 질문 입력의 중복 원문은 원문 참조로 묶는다. 큰 입력은 근거 묶음별 검토 후 원문 ID를 선별하여 최종 판정한다. 점수·대체 사실은 선별 단계에서 생성하지 않는다. 모든 원래 근거는 최초 선별 단계에서 검토하며, 원문 인용 그룹과 필수 표 행은 보존한다. 반대·제약 근거를 모두 제외하는 응답과 목록 밖 ID는 거절한다.
4. 묶음 선별 결과를 질문·원문·모델·정책 해시로 저장하여 재시작에서 재사용한다. 최종 판정의 인용은 실제 제공한 선정 원문에 한해 검증한다. 최종 점수는 기존 서버 규칙으로 계산한다.

## 검증

- 외부 AI 없는 DAC 오류·분할·복구·원문·점수 회귀 테스트: 76개, 하위 사례 24개 통과. 보고서 오류 처리와 입력 버전 호환 처리를 포함한 최종 전체 백엔드 검사 620개·하위 사례 166개 통과(의존성 폐기 예정 경고 2개).
- 개발 API 및 intake/analysis/report 워커에 반영. 데이터·계정·모델·평가 점수 규칙은 변경하지 않음.
- 브라우저의 DAC 평가 준비 → 평가 실행으로 실제 재실행 완료. 15:43:45–15:46:50 KST, 3분 5초. 원문 61개와 완료 질문 10개 재사용, 근거 선별 체크포인트 42개 저장, 11개 질문·5개 기준 모두 완료, 오류 없음.
- 종합 10.2/20, KOICA E. 적절성 2.0·일관성 2.5·효과성 1.7·효율성 1.5·지속가능성 2.5. 점수 규칙은 변경하지 않았다.
- 목표·실적 표 18개 행 전부 검토됨. CPCR 강사 목표 10명/실적 6명, 교육 운영 목표 4회/실적 6회 등 원문 수치가 검증 오류 없이 보존됐다. 목표시점·동일 기간 비교가 불명확한 수치는 비율 점수에서 제외되어 있음.
- 보고서 전체/섹션 생성 버튼이 활성화됨을 확인하고 전체 27개 섹션 작성을 실행했다. 20개가 저장됐고 나머지 7개는 24시간 토큰 보호 한도에 도달하여 생성되지 않았다. 공급자 400 재발이 아닌 서비스 자체 사용량 제한이다. HWPX 생성·다운로드는 아직 검증하지 못했다.

## 보고서 후속 점검

- 실행 `bda968d3-5a07-49ce-8ba4-2dca6a98f37d`: 표지·목차·사업/평가 개요·성과 달성도·기준별 평가·결론 등 20개 초안 저장. 등급표·국문 요약·작동요인·비작동요인·변화이론·환류과제·교훈 7개 생성 필요.
- 종합 결론은 완료된 DAC 10.2/20·E 등급을 반영했다. 생성 도중 새로고침해도 로그인과 작업은 유지됐다. 성과 달성도의 품질 점수 NULL은 AI 응답 값이며, 메타데이터상 대체 생성(fallback)은 사용하지 않았다.
- 사용량·인증·결제 등 전체 요청에 영향을 주는 오류는 남은 섹션과 대체 생성 요청으로 연쇄 진행하지 않도록 수정했다. 이전 성공 섹션은 보존하고 이어서 생성할 수 있다. 일부 섹션 실패 작업이 AI 작업 트레이에서 완료로 표시되던 문제도 수정했다.
- 오류 처리만 변경해도 전체 파일 해시가 달라져 기존 DAC와 초안을 오래된 결과로 표시하는 문제가 드러났다. 기존 QA 이미지의 파일과 비교했으며 새 오류 종류 import, 중단 오류 tuple, 두 예외 절을 제외한 AST가 동일함을 확인했다. 프롬프트·자료 구성·평가 규칙은 동일했다.
- 확인한 `assembled/report_generator` 해시 한 쌍만 입력 버전상 호환 처리했다: `6d385528facb08ab529993b23a8ff0b5e85b6b8a422bb9c1e512734fad150904` → `858766646b10215c3e81380be3d51b0baa623687fe2fb35b2cafa5c20dfacc09`. 실제 실행 메타데이터는 현재 파일 해시를 기록한다. 다른 변경이나 알 수 없는 해시는 계속 결과를 무효화한다. 브라우저에서 불필요한 DAC 재평가 요구가 사라지고 기존 20개 초안이 유지됨을 확인했다.
- 개발서버 토큰 한도를 3,000만에서 5,000만으로 일시 확대하는 승인을 요청했다. 작업당 $30·계정당 하루 $60·전체 하루 $100 비용 한도는 유지하는 조건이다. 아직 적용하지 않았으며, 승인 후 남은 섹션 생성과 HWPX 검증을 진행하고 기본 토큰 한도를 복원해야 한다.
- 운영서버에는 이번 변경을 배포하지 않았다.

## 한계와 후속 확인

근거 선별은 입력 한도를 피하기 위한 추가 AI 판단이다. 자료 없음으로 미실행을 단정하지 않도록 최종 입력에 범위를 명시하며, 검증되지 않은 ID나 원문을 인정하지 않는다. 모든 미래 공급자 오류가 없어졌다고 단정하지 않는다. 모델·자료 변경은 캐시 재사용 조건을 충족하지 않는다.

이번 검증은 DAC 중단 복구와 이후 보고서 흐름 확인이다. 앞선 사용자 흐름 QA에서 발견한 성과지표 단위·기간 비교와 증거 품질 문제를 모두 수정한 것은 아니다. 보고서 초안의 일부 문구 오류도 제출 전 검토 대상이며, 최종 제출 승인은 수행하지 않았다.
