# 일반 자료 실패 격리와 자동 산출물 분류

운영 조사 시 일반 자료 5건이 원문 매칭 검증 오류로 실패 또는 재시도 상태였다.
사업계획서 참고 인용, 업로드 원문 인용, DAC 분류 근거의 불일치가 문서 전체 실패로 전파됐다.
이 중 1건은 기존 재시도로 완료됐으며 배포 직전 4건이 실패 상태로 남았다.
사용자 중지 1건도 `status <> 'completed'` 조건에 포함되어 이후 작업을 계속 막았다.

## 처리 정책

- 일반 자료의 사업계획서·PDM·DAC 슬롯·보고서 자동 매칭은 선택적 제안이다.
  실제 제공 원문으로 확인되지 않는 제안은 제외하고, 확인된 제안과 요약을 보존한다.
  제안이 모두 제외되면 미분류로 완료한다. 매칭 인용 불일치로 AI를 다시 호출하지 않는다.
- DAC 라벨만으로 제외된 매칭을 다시 만들어내지 않는다.
- 사전 판단이 mixed/uncertain이거나 확신도가 0.85 미만이면 산출물로 등록한다.
  기존 저장된 사전 판단에도 적용하며 명시적인 사용자 처리 방식 선택은 유지한다.
- 일반 자료의 failed/cancelled 상태는 완료 문서의 성과 분석, DAC 평가, 보고서 생성·내보내기를 막지 않는다.
  해당 실패·중지 문서는 분석 대상에서 제외한다. 모든 문서가 실패·중지인 경우 실행할 수 없다.
- 진행 중인 업로드, 실제 AI 연결 대기, 필수 사업계획서·PDM 미완료와 실행 중인 평가의 동시 작업 제한은 유지한다.
- 실제 AI 생성/통신 실패와 파일 읽기 실패를 완료로 위장하지 않는다. 해당 문서에 원인을 남긴다.

## 복구와 검증

`tools/recover_intake_mapping_failures.py`는 기본 읽기 전용이다. `--apply`는 지정한
매칭 검증 오류의 failed/retry 일반 자료 및 기존 awaiting_review만 다시 큐에 넣는다.
완료·사용자 중지·실제 AI 통신 실패는 건드리지 않는다. 복구 전 오류를 processing_events에 보존한다.

`tools/qa_intake_failure_isolation.py`는 운영 데이터로 성과·DAC 계획과 시작 가능 상태를
확인하며 AI 요청 또는 평가 결과 변경을 하지 않는다.
