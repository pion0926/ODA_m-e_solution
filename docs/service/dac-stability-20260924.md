# DAC 운영 안정성 점검

## 확인된 원인

- 모델이 원문 줄 번호를 직접 생성하고 서버는 범위 밖 번호를 거부했다. 정수 형식·허용 범위가 공급자 응답 스키마에 지정되지 않았다.
- 형식 실패를 같은 입력으로 세 번 반복하고, 6,000자 이하 구간은 더 작게 나누지 않아 5,000자짜리 실제 실패 구간을 복구하지 못했다.
- 출력 한도·입력 한도와 통신 장애가 섞여 불필요한 형식 재시도로 이어질 수 있었다.
- 실패한 구간이 이후 문서·질문 작업을 막았고, 분할 성공 구간으로 덮인 상위 구간의 완료 여부를 인식하지 못했다.
- JSON 문자열의 NUL·단독 surrogate가 DB JSONB 저장 단계까지 도달할 수 있었다.

## 변경

1. 서버가 800자 이하 원문 조각과 ID를 만든다. AI는 허용 ID와 질문 ID를 구조화된 스키마로 선택한다. 줄 번호 및 인용문을 생성하지 않는다. 서버가 원문을 인용하며 출처·수치 검증은 유지한다.
2. 입력·출력 한도는 즉시 구간 분할, 형식 오류는 제한된 재시도 후 최소 1,200자까지 분할한다. 문서당 검증 오류 예산은 24회다. 네트워크 재시도는 별도 3회로 제한한다. 결제·인증·설정·거절은 형식 오류로 재시도하지 않는다.
3. 완료 구간, 미완료 구간, 완료 질문을 저장한다. 다른 문서·질문·기준은 가능한 범위에서 진행한다. 미완료 원문이 필요한 기준은 점수를 확정하지 않는다. 다음 실행에서 동일한 입력의 완료 범위와 질문 체크포인트를 재사용한다.
4. 질문 응답이 출력 한도에 걸리면 설명을 간결하게 요청하고 출력 한도를 12,000→18,000→24,000 토큰으로 제한적으로 확장한다. 이전의 큰 응답을 재시도 입력에 반복해서 붙이지 않는다.
5. BOM은 정상 처리하고, JSON 중복 키·NaN·Infinity·NUL·단독 surrogate를 저장 전에 거부한다. 추출 원문의 NUL·단독 surrogate 잡음은 공백으로 치환해 위치 길이를 유지한다. 원본 파일은 바꾸지 않는다.
6. 원문·질문 체크포인트의 일시적 DB 저장 오류는 AI를 재호출하지 않고 같은 저장 작업만 최대 3회 재시도한다. 진행 단계도 보존·표시한다.

## 검증

- 원문 ID·범위·허위 인용, 긴 인용, 부분 재개, 질문별 실패 격리, DB 저장 오류, HTTP 408/429/5xx·timeout, 응답 구조, 인코딩과 출력 한도 테스트.
- DAC 준비 화면 → 실제 API → DB 저장의 격리 브라우저 통합 검증.
- 사용자 승인 후 실제 실패 구간을 openai/gpt-5.6-luna로 검증: 36,000–41,000자 구간은 1개 구간/근거 34건, 23,000–48,000자 구간은 2개 구간/근거 24건. 평가 결과·문서 캐시는 수정하지 않았고 정상 토큰 사용량만 기록했다.

## 운영 경계

공급자의 지속 장애·잔액 부족·인증 오류·원본 손상·지속적인 DB 장애까지 성공으로 바꾸지는 않는다. 미완료 상태와 원인을 남기고 완료 결과를 보존한다. 허위 인용, 미확인 수치 또는 누락 구간을 정상 완료로 처리하지 않는다. 실제 전체 DAC 평가를 이 검증에서 자동 실행하지는 않았다.
