# DAC 원문 범위 탐색과 자동 선택 이력

## 원인

질문별 원문 구간을 찾을 때 현재 질문과 무관한 PDM·사업계획 연결 인용과 모든 DAC 기준 인용에 같은 가중치를 주었다. 현재 질문의 사실이 다른 위치에 있어도 관련 없는 인용이 많은 구간을 먼저 선택할 수 있었다. 이전 실행의 문서 선택은 자동 제안과 사용자 변경을 구분하지 않아, 기존 문서의 자동 매핑이 바뀌어도 이전 선택이 남았다.

## 변경

`dac-focused-v3`은 현재 질문의 등록 사실과 현재 DAC 기준에 연결된 인용만 탐색 가중치에 반영한다. 이는 원문 위치를 찾는 용도이며 요약을 평가 증빙으로 대신 사용하지 않는다.

새 실행에는 자동 제안과 비교해 사용자가 추가·제외한 문서 식별자를 질문별로 기록한다. 이후 자동 연결 변경은 반영하고 명시적 추가·제외는 유지한다. 수동 변경을 구분할 수 없는 과거 실행은 기존 선택을 유지한다. 문서 삭제·평가 제외된 식별자는 새 선택으로 넘기지 않는다.

실제 HTTP 통합 검사에서 근거 부족 시 추가 원문 탐색이 사용자가 질문에서 제외한 문서까지 되살리는 경계를 발견했다. 추가 탐색과 실패 작업 재개 모두 질문별 명시적 제외를 확인해 해당 문서를 다시 읽지 않도록 수정했다. 다른 질문에서 선택된 같은 문서의 검토는 유지한다.

## 검증 및 제한

질문 사실 우선 범위 선택, 자동 연결 변경, 수동 추가/제외 보존, 과거 선택 호환성, 자동확장 및 재개를 검증했다. 관련 회귀 32개 통과. 실제 격리 QA HTTP/PostgreSQL 통합 39개에서 명시 제외된 질문에는 해당 문서 원문 검토 캐시가 생성되지 않는 것도 확인했다.

운영 사전계획의 57개 선택 문서·419개 문서/질문 쌍은 전체 원문 전송이 아니다. 문서별 선택 구간을 합친 길이는 약 63.7만 자로 해당 문서 전체 약 284.4만 자의 22.4%였다. 원문 검토는 중복 구간을 합치고 검토 캐시를 사용한다.

기준 단위 매핑은 같은 DAC 기준의 여러 질문을 선택할 수 있다. 질문 사실이 존재한다는 이유만으로 다른 질문의 기준 연결을 버리면 아직 추출되지 않은 근거를 놓칠 수 있어, 이번 변경은 그 선택 의미를 바꾸지 않는다. 과거 자동·수동 구분이 없는 선택 역시 자동으로 축소하지 않는다.
