# DAC 근거 선별 캐시가 JSONB 재로딩 후 누락되는 오류

상태: 소스 수정, 합성 회귀 검증. 진행 중 운영 평가는 변경하지 않는다.

## 재현과 원인

판정 프롬프트 v15 운영 재평가에서 원문 사실 57개 문서·206개 구간은 재사용되었으나, 질문별 근거 선별 요청이 다시 발생했다. 첫 번째 질문의 선별 묶음 7개를 읽기 전용으로 비교했다. JSONB에서 읽은 사실로 계산한 키는 직전 v14 캐시와 0/7, 실행 중 v15 캐시와 7/7 일치했다. 값·근거 ID를 그대로 두고 최초 추출 객체의 키 순서만 메모리에서 복원하자 v14 캐시와 7/7, v15 캐시와 0/7 일치했다. 근거 값과 ID는 완전히 동일했다.

기존 캐시 digest가 `sort_keys` 없이 직렬화되어 Python 객체 생성 순서와 PostgreSQL JSONB의 객체 키 정렬을 다른 입력으로 취급한 것이 원인이다. 판정 프롬프트 변경 자체나 원문 변경이 원인은 아니다. 프롬프트 버전만 변경하는 단위 검증은 통과했지만 실제 저장 경계를 통과하는 검증이 부족했다.

## 수정

- 선별 버전·현재 모델·질문 정의·근거 전체를 재귀적 키 정렬로 직렬화해 digest를 계산한다. 원문, 필드, 배열 순서와 근거 ID는 제거하거나 느슨하게 비교하지 않는다.
- 기존 캐시는 **현재 입력을 종전 방식 그대로 직렬화한 키**가 일치할 때만 후보로 사용한다. 과거 키 순서를 추정하거나 유사한 캐시를 검색하지 않는다.
- 후보의 허용 근거 ID, 반대 근거 보존, 연속 인용 묶음을 다시 검증하고 canonical 키로 현재 실행에 저장한다. 현재 입력의 검증된 선별 결과를 새 실행에도 전달하여 제한된 실행 이력에 의해 유효 캐시가 사라지는 것을 줄인다.
- 원문 추출 및 질문 판정 버전·digest를 변경하지 않는다. 실행 중 평가와 저장된 점수를 조작하지 않는다.

## 검증 범위

회귀는 최초 객체→JSONB 형태의 키 정렬→재사용, 정확한 기존 키의 승격, 다른 과거 순서 키를 추정하지 않음, 무효 근거·반대 근거 누락 검증, 원문·질문·모델 변경 시 캐시 무효화를 포함한다. DAC·안정성 테스트 196개 및 하위 검증 51개가 통과했다. `tools/qa_dac_question_reuse.py`의 실제 PostgreSQL JSONB 왕복·canonical 저장·RLS·일반 실행 재사용 등 총 8개 검사도 통과했다. 테스트는 합성 데이터·모의 AI만 사용했으며 QA DB 변경은 모두 롤백했다.
