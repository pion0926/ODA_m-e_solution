# 해제된 과거 분석 조합을 다시 수동 연결할 수 없는 문제

## 재현과 원인

문서 A를 지표 1에 분석한 뒤 목적 재분류로 연결이 해제되면 유효한 과거 분석 이력은 보존된다. 그러나 준비 화면이 모든 `analyzed_document_ids`를 선택 목록에서 제외하고 API도 동일 집합을 409로 거절했다. 따라서 현재 연결된 조합의 중복 실행을 막는 조건이 현재 미연결인 조합의 명시적 복원까지 차단했다. 운영 데이터 변경 없이 합성 데이터로 재현한 기능 버그다.

## 수정

- 현재 프로젝트에서 활성·완료 상태이고, 현재 연결이 없으며, 재사용 검증을 통과한 과거 문서×지표 조합만 `restorable_document_ids`로 제공한다. 자동 선택하지 않는다.
- 사용자가 직접 선택하면 `restored_mappings`에 넣고 실행 대상 `mappings`에 복원한다. 신규 원문 추출 대상 `new_mappings`에는 넣지 않는다. 기존 측정 근거로 최신 비교·집계를 다시 적용한다.
- 현재 연결된 과거 조합의 중복 신규 요청은 계속 거절한다. 모델·원문·지표의 캐시 검증 규칙상 유효하지 않은 조합은 기존 신규 분석 경로를 사용한다.
- 명시적으로 복원한 조합은 수동 포함으로 기록하고 해당 수동 제외만 해제한다. 선택하지 않은 과거 조합이나 다른 제외 항목은 바꾸지 않는다. 평가 제외 문서·다른 프로젝트 문서는 복원할 수 없다.
- 준비 화면에서 `분석·연결 복원할 문서`로 표시하며 신규 분석 건수와 기존 결과 재사용·복원 건수를 구분한다. 새로고침해도 유효한 복원 선택을 유지한다. 작업 완료 메시지에도 복원 건수를 표시한다.

## 검증과 범위

백엔드 합성 회귀: 복원 후보 노출, 기본 미선택, 기존 연결 중복 요청 차단, 복원만 실행 시 원문 추출 함수 호출 0회 및 과거 검증 실적 복구, 목적 재검토 보류 해소, 수동 포함·제외 의도 보존, 낡은 캐시 신규 분석, 제외/외부 문서 거절. 프런트 동작 검증: 후보·표 헤더·건수·실행 버튼, 새로고침 후 복원 선택 유지, 제출 데이터.

변경은 코드와 테스트에 한정한다. 운영 문서·매핑·평가 결과를 수동 변경하거나 실행 중 DAC를 중단하지 않았다. 원문 측정 AI 재호출을 생략하는 것이며, 변경된 지표의 위험·보완 분석은 정상 실행 정책에 따라 다시 수행할 수 있다. 배포·실제 적용 여부는 해당 릴리스 검증 기록을 따른다.
