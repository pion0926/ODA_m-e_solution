# 실적보고의 증빙 신뢰도를 지표 범위 불일치로 오판한 사례

## 원인과 재현

개발 프로젝트 자료 재매핑 중, 등록된 지표와 동등한 실적을 보고한 표가 `reported_result`, 대상·활동 일치, 연결 신뢰도 0.96으로 분류됐지만 `scope_match=false`로 제외됐다. 사유는 측정 기관·집단·사업·기간의 불일치가 아니라 원본 대장·제3자 확인 자료의 미첨부였다.

기존 프롬프트에 이미 이 구분을 명시했으나 동일 모델에서 오류가 재발했다. 단순 프롬프트 지시 강화만으로는 해당 실적보고의 누락을 막지 못했다.

## 수정

`pdm_scope_review.py`에서 `reported_result`이며 대상·활동 일치, 연결 신뢰도 0.75 이상, 원문 인용이 존재하지만 범위만 불일치한 후보를 독립 재검증한다. 등록 PDM 지표, 사업계획 맥락, 해당 후보의 기존 원문과 한계만 사용한다.

- 원본 대장·독립 확인 자료 미첨부는 한계로 유지하며 그 사유만으로 범위를 불일치 처리하지 않는다.
- 다른 사업·기관·집단·부적합한 기간/단위는 제외를 유지한다.
- 새로운 숫자나 인용을 만들거나 원문·연결 신뢰도를 바꾸지 않는다.
- 결과는 매핑 후보의 범위 검증이며 성과 수치의 확정·인증이 아니다. 실제 성과 분석에서 별도 원문 검증한다.
- 동일 연동 모델을 사용하고 응답 검증 재시도는 2회로 제한한다. 공급자/응답 오류 시 참고 항목으로 남겨 일반 자료 등록을 막지 않는다. 전송 재시도 소진·요금·설정·거절·키 누락은 별도 종료 예외 계층이므로 명시적으로 처리하며 추가 재요청을 하지 않는다. 사용자 중지와 작업 예산 경계는 삼키지 않는다.
- 최초 판정, 검증 사유, 모델, 검증 버전을 저장하고 해당 모듈을 프롬프트 매니페스트에 포함한다.

이미 준비한 후보에는 `remap_evidence_purpose review-scopes`로 이 조건에 해당하는 항목만 적용할 수 있다. 현재 원문·기준문서·v4 일치를 검사하며 다른 원문 분석이나 평가 결과는 수정하지 않는다.

## 검증

- 격리 QA에서 관련 회귀 38개 및 2개 하위 사례 통과. 공급자 종료 예외 5종의 참고 상태 유지와 사용자 중지·작업 예산 예외의 정상 전파를 포함한다.
- 다른 사업 범위는 제외 유지, 목표/선행활동/낮은 신뢰도/대상 불일치는 추가 API 없음, 실패 시 미분류·참고 유지, 원문 보존, 반복 실행의 중복 호출 방지를 검증.
- 개발 56건의 준비 후보를 검토해 오류 없이 8개 직접 매핑 확인. 조건에 해당하는 후보 1건만 동일 Luna로 재검증해 1개 직접 매핑 복구. 전체 56건의 source/hash/version 검증 후 총 9개 연결 후보를 확인했다.
- 개발 환경의 일관된 암호화 백업 후 56건 후보를 정식 유지보수 도구로 적용했다. 성과 분석 정식 API에서 신규 7쌍·기존 유효 2쌍 중 신규 대상만 실행했고, 문서 5건·측정값 6건·지표 14개 저장을 완료했다. 미완료 지표는 0건이다.
- CPCR 강사 실적은 원문 기준 6명으로 반영됐다. 완료 후 사전검토를 다시 요청하면 신규 분석 쌍 0건·변경 지표 0개가 반환되어, 같은 자료에 대한 반복 분석을 요구하지 않았다.
- 이 개발 검증은 MCI 문서 2건을 의도적으로 제외한 구성이다. 해당 지표의 실적 미확인은 이 구성에서 정상이며 임의로 운영 실적을 복사하지 않았다.
