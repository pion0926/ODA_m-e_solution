# 보고서 진입 시 과거 완료 기록이 진행 중 작업 트레이를 덮는 문제

## 원인

보고서 작업의 최신 상태 조회는 완료 응답을 받으면 반복 조회를 멈춘다. 다른 창에서 새 전체 작성을 시작하면 공통 작업 트레이의 경량 조회는 새 진행률을 표시하지만, 보고서 화면의 `latestGenerationStatus`에는 이전 완료 기록이 남을 수 있다.

섹션 목록·본문을 읽을 때 이 과거 기록을 화면에 다시 렌더링했고, 렌더러가 전역 `report` 작업도 갱신했다. 그 결과 진행 중인 작업이 일시적으로 완료로 표시되었다가 다음 트레이 조회에서 복구되었다. 백엔드 작업의 상태나 저장된 본문이 바뀌는 결함은 아니다.

## 수정

- 캐시된 생성 기록의 화면 렌더링과 전역 트레이 갱신을 분리한다. 새 상태 조회·중단 API의 응답만 생성 상태를 트레이에 반영한다.
- 보고서 화면에 진입할 때 기존 최신 생성 상태 조회를 실행하여, 다른 창에서 시작된 작업의 진행률과 실행 버튼 상태를 다시 동기화한다.
- 기존 작업 트레이 조회 주기, 서버 API, 작업 실행·저장·취소 정책은 유지한다.

## 검증

`redesign/frontend/test_report_tray_freshness.cjs`는 실제 컨트롤러 함수와 작업 트레이 모듈을 합성 DOM에서 실행한다. 이전 완료 기록과 새 진행 작업이 공존할 때 섹션 화면 재렌더가 트레이를 변경하지 않는지, 화면 진입이 새 작업을 조회하는지, 늦게 도착한 이전 조회 응답이 무시되는지, 실제 완료 응답은 정상 반영되는지 확인한다. 수정 전 소스에서는 첫 검증이 실패하고 수정 후에는 통과한다.

전체 프런트 회귀 27건 통과. 실제 서비스 반영과 배포 후 화면 검증은 별도 단계다. 이 변경에는 백엔드·DB·프롬프트 수정이나 유료 AI 호출이 없다.
