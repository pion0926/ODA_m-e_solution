# 보고서 상단의 저장 본문 수와 이번 생성 진행률 혼동

## 재현

이미 본문이 저장된 27개 섹션을 전체 재생성하면, 이번 작업은 9/27 진행 중이어도 상단에 `작성 27 · 생성 중 0`이 표시될 수 있었다. 상단은 저장된 섹션 상태만 집계하고 작업 트레이는 현재 batch의 실행 상태를 사용하여 서로 다른 집계가 구분 없이 노출됐다.

## 수정

프런트의 기존 `latestGenerationStatus`와 섹션 목록을 함께 사용한다. 전체 생성이 queued/running이면 `27개 섹션 · 저장된 본문 27 · 이번 생성 9/27`로 표시한다. 대기 상태와 이번 작업의 실패 건수도 구분한다. 생성 상태만 갱신되어도 상단을 갱신하며, 뒤늦은 섹션 목록 조회가 현재 작업 진행률을 이전 본문 건수로 덮지 않게 했다. 전체 작업이 종료되면 기존 섹션별 작성·생성 중·확인 필요 집계로 돌아간다.

서버·DB·실제 생성 작업·정책·폴링 횟수는 바꾸지 않았다. 기존 본문이 있다는 표시가 이번 생성 완료나 자료 최신성을 뜻하지 않는다.

## 검증

오프라인 프런트 회귀 **4개 통과**: 기존 본문 27개와 진행 9/27, 상태만 바뀐 10/27 및 실패 건수, 목록 재조회, 대기 상태, 완료 후 정상 집계, 빈 본문, 기존 중지/상태/AI 요청 UI 계약. 추가 API 호출 없이 검증했다. 운영 화면에서 발견한 문제이며 배포 후 화면 확인은 해당 릴리스 QA 기록을 따른다.
