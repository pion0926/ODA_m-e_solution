# 사업명 오분류와 목차 쪽수 부분 검증

사용자가 V2.4.10의 knut 보고서에서 표지의 `학과신설:` 접두어와 목차 번호 누락을 발견했다. 기존 QA는 파일 완성·슬롯·하위 목차만 검사했고 사업명 근거의 의미와 모든 목차 행을 확인하지 못했다.

## 원인

- 계획서 73쪽 예산표의 `학과신설`은 원문에 존재하지만 전체 사업의 이름이 아니다. 필드 사실 추출에서 인용의 존재만 확인했고 사업명 필드인지 검증하지 않았다. 개요 생성 결과가 이를 확장해 `학과신설: ...`이라는 제목을 만들었다.
- 표지와 내보내기 이름은 그 잘못된 개요를 그대로 사용했다. 기존 초안에도 잘못된 제목이 남았다.
- 목차 항목을 여러 모듈에서 각각 관리했고, 하위 20개만 필수 목록에 있었다. 평가등급표와 I·II·III·V·VI 장 제목 6개는 표시되지만 쪽수 검사를 받지 않았다.
- 번호를 찾지 못하면 상위 XML 문단의 다른 행 번호를 사용할 수 있었다. 검증 함수도 계산 결과에서 빠진 항목을 건너뛰었다.

## 수정

- `project_identity.py`: 현재 명시적 사업계획서의 앞부분 사업명/국문 필드, 이후 표지 순으로 실제 연속 원문과 위치를 확인한다. 예산표·세부 과업·연계 사업을 사업명으로 채택하지 않는다. 공식 명칭이 없거나 충돌하면 등록된 프로젝트 이름을 출처와 함께 사용하거나 확인 필요로 둔다. 긴 영문 풀이만 표시 제목에서 제외하고 원문 인용은 보존한다.
- 신규 업로드에서 사업명은 위 규칙으로 등록한다. 다른 사실은 계속 분석하며 잘못된 AI 사업명 후보만 버린다. 사업명 추출 프롬프트도 필드 용도를 명시한다.
- 기존 AI 출력은 변경하지 않고 조회·생성 문맥·내보내기에서 검증된 사업명을 적용한다. 표지·사업개요·평가등급표의 사업명 슬롯만 교체하며 점수·평가 근거·본문을 보존한다. 원래 AI 제목과 새 제목의 출처를 조회 결과에 남긴다.
- `toc_registry.py`에 표시되는 26개 항목을 일원화했다. Kordoc와 rHWP는 모든 장 및 항목의 실제 본문 위치를 찾고, 최종 파일을 다시 조판해 쪽수가 수렴하는지 확인한다.
- 번호 없는 장 제목에도 고정 번호 셀을 만든다. 타 행 번호를 차용하지 않으며 26개 중 계산/표시가 누락되면 완료로 내보내지 않는다. 첫 행은 목차 장식 아래 별도 여백을 확보했다.
- 최종 표지·평가등급표·사업개요에 공식 사업명이 실제 들어갔는지 검사한다.
- 제목 메타데이터 수정 때문에 기존 평가·본문을 전부 재생성하지 않도록 검토한 정확한 세 소스 해시만 입력 호환으로 기록했다. 실제 실행 소스 해시는 그대로 기록되고 알 수 없는 변경이나 새 문서/평가 입력은 기존처럼 무효화된다.

## 검증

- 백엔드 전체: 703 passed, 166 subtests passed. 기존 라이브러리 deprecation 경고 2개.
- 운영 원문 읽기 전용 확인: 공식 사업명은 계획서 **5쪽 국문 사업명**에서 추출되었다.
- 기존 실제 61쪽 파일 복사본: 26개 목차 항목 전부 검증, 쪽수 수렴, 첫 행 장식 겹침 제거. 추가 AI 호출 없이 개발 조판 서버와 rHWP에서 확인했다.
- 개발 서버 API·워커 모두 healthy, 기존 평가 입력 호환성 검증 통과.
- 운영 배포 및 새 HWPX 검증 결과는 사용자 흐름 QA 문서에 이어 기록한다.

기존 HWPX 파일 자체는 보존한다. 수정 후 새로 내보낸 파일이 교정된 산출물이다.
