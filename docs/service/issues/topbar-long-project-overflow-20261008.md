# 긴 사업명과 작업 버튼의 상단바 가로 넘침

## 확인한 문제

운영 성과지표 화면의 1032px 브라우저에서 문서 가로 길이가 1108px까지 늘어나 AI 작업·증빙 업로드 버튼이 화면 오른쪽 밖으로 밀렸다. 본문 카드가 아닌 상단바에서 발생했다.

기본 `.topbar`가 높이 54px의 한 줄 flex였으며 줄바꿈은 920px 이하에서만 허용했다. 중간 폭에서는 246px 왼쪽 메뉴를 제외한 공간에 경로·긴 사업명·갱신 문구·버튼을 모두 배치할 수 없었다. 버튼도 flex 축소 대상이어서 문구가 좁게 찌그러졌다.

## 수정

- 모든 폭에서 필요한 경우 상단바가 줄바꿈하고 내용에 맞춰 높이를 확보한다.
- 사업명 칩은 최소 폭 0 및 부모 폭 이내로 제한하며 기존 말줄임을 유지한다.
- 경로·갱신 문구는 긴 문자열도 줄바꿈한다.
- 상단 작업 버튼은 축소하지 않고 다음 줄에 배치한다. 기존 작은 화면의 로그아웃 버튼 및 숨김 규칙을 유지한다.

변경은 `assets/app-styles.css`의 상단바 규칙으로 제한했다. API·본문 화면·사용자 데이터·분석 및 보고서 정책은 변경하지 않았다.

## 검증

`tests/e2e/topbar-layout.spec.cjs`는 실제 `frontend/index.html`의 상단바·사이드바와 실제 서비스 CSS를 로컬 정적 서버에서 사용한다. API와 외부 origin은 차단하고 긴 한글 사업명과 공백 없는 긴 영문 사업명으로 검사한다.

- 1440·1032·921·800·541·390·320px에서 문서 가로 스크롤이 발생하지 않는다.
- 표시된 상단바 요소가 상단바 경계 안에 있으며 AI 작업·증빙 업로드 버튼을 클릭할 수 있다.
- 사업 선택 → AI 작업 → 증빙 업로드의 Tab 순서와 작은 화면의 로그아웃 접근을 유지한다.
- 두 Playwright 프로젝트에서 통과했다. 각 프로젝트는 두 사업명 × 일곱 화면 폭을 검사한다.
- 같은 앱 CSS를 쓰는 로그인·성과 분석 사전 검토·DAC 보완 안내를 함께 실행해 총 14개 Playwright 검사가 통과했다.

동일한 합성 화면의 수정 전후 비교에서 1032px 기준 가로 길이가 1247px에서 1017px로 줄고 상단바 높이가 54px에서 89px로 증가했다. 합성 문구가 실제 운영 문구보다 길기 때문에 최초 운영 측정값과 넘침 크기는 다르다. 1032px·390px 화면 캡처도 육안 확인했다. 캡처는 커밋하지 않는 `.runtime/topbar-layout-qa/`에 보관한다.

운영 반영과 실제 운영 화면 재확인은 별도 배포·QA 기록을 따른다.
