# 보고서 검증 보완 배포 후 평가 최신성 오판

상태: 정확한 소스 해시 호환 추가. 운영 DB를 변경하지 않고 새 이미지 반영으로 복구한다.

## 원인 확인

V2.4.31은 보고서의 서버 고정 잠정평가 안내문을 기관명 혼입 검사에서 제외하는 한 줄의 검증 수정이었다. 그러나 평가 입력 지문에 `report_generator.py` 전체 파일 해시가 포함되어, 자료·PDM·DAC 결과가 바뀌지 않았는데도 기존 평가를 오래된 것으로 표시했다.

V2.4.30/V2.4.31에 실제 포함된 파일을 `read_bytes()`로 확인했다. 기존 해시는 `341c9080e3447b7c690e77e31de2712931603a91f60abace9ebf5cf58de46b73`, 새 해시는 `8ac4b134943bf48a9482a06c65800ac76cb3b0a77b7a30d6e002fed90b59012e`다. 새 파일에서 `koica_check_text = koica_check_text.replace(PROVISIONAL_NOTICE, "")` 한 AST 할당문만 제외하면 두 AST가 동일했다. 프롬프트·원문·점수·저장 본문은 바뀌지 않았다.

운영 입력을 읽기 전용으로 조회하여 해당 해시 하나만 이전 해시로 바꿔 계산했을 때, 새 workflow digest가 저장된 평가의 digest와 정확히 일치했다. 타임존이나 문서 상태 변화가 원인은 아니었다. 운영 데이터나 캐시는 수정하지 않았다.

## 수정 및 검증

기존 `compatible_input_manifest`의 정확한 해시 대응에 이 한 쌍만 추가했다. 실제 배포 소스 지문은 계속 새 해시로 기록한다. 알 수 없는 후속 버전, 다른 프롬프트, DAC 기준 변경에는 호환을 적용하지 않는다. 판정 결과·보고서의 유효성 검증도 생략하지 않는다.

회귀는 이 보고서 검증 수정의 평가 입력 지문 동일성, 실제 배포 지문 보존, 다른 프롬프트·DAC 정책·루브릭·미검토 후속 버전 변경 시 무효화를 검사한다. 관련 최신성·보고서 회귀 99개 및 하위 검증 2개가 통과했다. 광범위한 지문 설계 변경 없이 검증한 운영 수정만 호환한다.
