# HWPX 대기 중 신규 자료 업로드와 오래된 보고서 출판 방지

## 원인과 재현

일반 자료는 보고서 작업 중에도 업로드할 수 있다. 내보내기 API는 접수 시점의 보고서 최신성을 검사하지만, 기존 작업자는 실행을 시작한 시점의 입력을 새 기준으로 삼고 보고서 최신성을 다시 확인하지 않았다.

따라서 내보내기 접수 후 신규 자료가 등록·분석되고 작업자가 뒤늦게 실행되면, 오래된 27개 섹션을 새 입력 스냅샷과 함께 내보낼 가능성이 있었다. 실행 마지막의 스냅샷 비교는 작업자 시작 이후 변경만 잡으므로 이 경계를 해결하지 못했다. 격리 합성 재현에서 오래된 보고서 조건임에도 렌더링 컨텍스트로 진입하며 최신성 검사가 호출되지 않는 것을 확인했다. 실제 AI·DB·운영 파일에는 접근하지 않았다.

## 수정

- 접수 시 현재 입력 스냅샷을 기존 작업 큐의 세 번째 인자로 전달한다. DB 스키마 변경은 없다.
- 작업자 시작 시 보고서 최신성과 접수 스냅샷 일치를 확인한다. 27개 본문의 hard validation을 다시 수행하고 점검 도중 입력 변경도 확인한다.
- 기존 두 인자 대기 작업도 실행할 수 있으나 동일한 현재성·본문 검사를 반드시 거친다.
- 본격적인 AI·조판 전에 오래된 요청을 실패 처리한다. 완료 직전 입력·본문 해시 비교도 유지한다.
- 기존 완료 파일은 그대로 보존한다. 실패한 새 요청을 완료 상태로 표시하거나 다운로드 가능하게 만들지 않는다.

## 검증

내보내기 최신성·보고서 재개·프로젝트 최신성·작업 모델 회귀 **44개와 하위 사례 5개 통과**.

문서·평가·매핑의 접수 이후 변경, 준비 검사 도중 변경, 실패 섹션, 기존 큐 인자 호환 및 프로젝트 범위, 오래된 27개 섹션의 조판/AI 진입 차단, 실패 상태 저장, 기존 완료 파일 바이트 보존을 확인했다. 현재 보고서의 동일 입력 내보내기는 허용한다.

## 기존 보존·검증 경로 확인

보고서 재개는 최신 실패/중단 실행과 동일 입력에 속한 완료 섹션만 보존하며 반복 재개의 상속 목록을 유지한다. 섹션 생성 실패는 새 후보를 별도 진단 메타데이터에 남기고 기존 본문을 덮어쓰지 않는다. HWPX는 고정 원본 양식의 해시를 검사하고, kordoc 조판 후 최종 rHWP 바이트를 다시 렌더하여 목차를 수렴시킨다. 완료 파일은 고유 export ID 경로에 저장하며 실패 후보는 비공개 진단 경로로 분리한다.
