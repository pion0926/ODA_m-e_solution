# DAC 개선 안내 및 다른 사업 적용 검토

## 구현

분석결과의 DAC 기준별 상단에 평가점수 개선 팁을 표시한다. 저장된 질문별 `scoring_trace`에서 판정·비교 조건 확인, 증빙 보완, 성과 개선을 구분한다. 항목에는 해당 질문, 현재 판단, 다음 조치, 필요한 자료가 표시된다. 기준별 묶음은 기본 접힘이며 자료 등록·연결, DAC 평가 계획으로 이동할 수 있다.

팁은 조회 시 계산하며 AI를 추가 호출하거나 기존 점수·평가·보고서를 변경하지 않는다. 기준 문서·매핑이 바뀌면 기존 lifecycle의 stale 정보를 표시한다. 자료 미확인과 실제 미달을 구분하고 원문 수치 검증 실패·비교 불가능·목표시점 미도래·점수 상한·4점 조건도 안내한다. 이전 형식/빈 평가에서는 재검토를 안내한다. 점수 상승을 약속하지 않으며 보완 후 명시적으로 재평가해야 한다.

## 흐름과 코드 검토

- 기본 문서 → 등록·매핑 → 명시적 PDM/DAC 검토·실행 → 결과 → 보고서 흐름을 유지한다. 신규 안내는 결과 조회에만 연결된다.
- 데이터 조회는 기존 project/tenant connection과 RLS 경계를 이용하며 다른 프로젝트 자료를 새로 가져오지 않는다.
- 다른 사업 초안에 혼입될 수 있는 report_sections.bootstrap_contents의 응급의료·학과 개설·취업·Job-Code 등 고정 사실을 제거했다. 사업별 저장 정보와 평가 결과만 이용하며 정보가 없으면 확인 필요로 남긴다. PDM 초안을 사업개요 정보로 대신 채우지 않는다.
- HWPX의 표 구조는 서비스의 표준 27개 섹션 양식에 맞춘 계약이다. 원본 사업별 HWPX 양식을 그대로 가져오는 기능은 아니다. 기존 긴 셀·가변 성과지표·매트릭스 분할·목차·원문 보존 회귀 검사를 포함했다.
- 테스트 실행 시 오래된 QA 이미지의 조판 설정을 읽던 문제를 수정했다. Test-Service가 검사 대상 workspace의 품질 설정을 명시한다. 로그인 복구를 위한 유일한 인라인 부트스트랩도 구조 검사에서 명시적으로 검증한다.

## 검증

- 전체 백엔드 747건, 하위 검사 166건 통과.
- 프런트 계약/상태 검사 18건 통과.
- Playwright 18건 통과: 데스크톱/작은 화면, 팁 접힘·펼침, 390px에서 긴 문자열, HTML 이스케이프, 미리보기 및 HWPX 렌더/round-trip.
- 보건·농업·전자정부·취업 등 합성 항목으로 샘플 고유 사실이 안내에 혼입되지 않음을 확인.
- 개발서버 기존 2개 프로젝트의 완료 평가에서 각각 5개 기준의 안내 생성 성공. 실제 점수/문서를 수정하지 않음.

## 범위와 남은 제약

이번 검증은 코드/회귀/기존 저장 결과/브라우저를 대상으로 한다. 다른 실제 사업의 전체 문서를 외부 모델에 보내 처음부터 유료 재분석하지 않았다. 문서 파싱과 모델의 사실 추출 정확성은 추가 실데이터 검증이 필요하며, 모든 문서·모델의 무오류를 보장하지 않는다.

보고서 생성기의 과거 우수사례 혼입 탐지는 일부 국가/고유명사 규칙이 남아 있어 포괄적인 출처 단위 의미 검증을 대체하지 못한다. 기존 보고서에 이미 저장된 샘플 문장은 이번 변경으로 자동 덮어쓰지 않는다. 한컴 데스크톱 검증은 수행하지 않았다. 오프호스트 백업은 사용자 요청대로 제외되어 있다.
