# 최종 목차의 물리 쪽수와 인쇄 쪽번호 불일치

## 원인과 재현

목차는 PDF/브라우저에서의 물리 페이지 인덱스를 사용했지만, 템플릿은 표지 뒤에서 번호를 다시 시작한다. 구역별 번호 재시작도 물리 인덱스와 인쇄 쪽번호를 다르게 만든다. 기존 최종 조판 검증은 같은 물리 인덱스끼리 비교하여 인쇄물에서의 차이를 놓쳤다. 실제 문서와 검증 관측값은 비공개 로컬 QA 결과에 보존한다.

## 수정

- 목적지 탐색과 문서 내 이동 좌표는 기존 물리 쪽수로 유지한다.
- 최종 rHWP SVG에서 표 셀에 속하지 않는 중앙 하단의 실제 쪽번호를 읽는다. 개별 숫자 글리프를 페이지 좌표로 변환하고 같은 기준선에서 왼쪽부터 합쳐, 예를 들어 `1`과 `8`을 `18`로 판독한다.
- 현재 서비스의 쪽번호 장식 `- 숫자 -`를 확인하고, 인쇄 목차에는 관측된 번호를 사용한다. 최종 검증 메타데이터에는 인쇄 `page_map`과 이동용 `physical_page_map`을 따로 보관한다.
- 표지·번호 숨김·구역별 번호 재시작을 일괄 `-1` 보정으로 처리하지 않는다. 목적지에서 번호가 없거나 여러 개라면 추정하여 완료하지 않고 원본을 보존한다.
- 평가 결과, 보고서 섹션 본문과 기존 완료 파일은 변경하지 않는다. 정상 HWPX 내보내기로 목차만 다시 조판한다.

## 환류표 가독성

서버가 조립한 환류표의 우선순위·선정 사유·완료기한·점검주기·확인자료 필드에서 동일 접두어가 연속되면 표시할 때 한 번만 남긴다. 해당 열과 필드 시작 부분으로 범위를 제한하며, 저장된 본문·다른 표·일반 문장·숫자·날짜는 유지한다. 반복 적용 안정성과 데이터 보존을 합성 회귀로 확인한다.

## 검증

합성 SVG의 분리 숫자·좌표 변환·숨긴 푸터·본문/표 안 숫자·다중 푸터와 실제 인쇄 번호 재시작을 회귀 검증한다. 최종 쪽번호를 반영한 파일을 다시 렌더하여 모든 목적지의 목차 번호와 관측된 인쇄 번호를 비교한다. 실제 검증 결과는 최종 QA 기록에 남긴다.

관련 합성 회귀 54개 및 하위 검사 6개가 통과했다. 오프라인 최종화 검증에서는 서버의 JavaScript 판독기와 별도로 Python XML 판독기로 모든 목차 행의 실제 마지막 셀 숫자와 목적지 푸터를 대조한다. 대조 완료 전에는 기존 목차 휴리스틱 경고를 해결된 것으로 취급하지 않는다.
