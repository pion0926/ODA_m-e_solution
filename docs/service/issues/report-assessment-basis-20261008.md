# 보고서의 잠정 평가 성격·PDM 기준 문서 일관성

상태: 코드 수정 및 보고서/HWPX 합성 회귀 검사 완료. 실제 운영 재생성·조판·화면 검증은 전체 흐름 검증에서 별도 기록한다.

## 발견한 문제

- 신규 DAC 산식은 `provisional_document_review`를 저장하지만 보고서 작성기는 종합점수를 “공식 종합판정”으로 강제했다. HWPX 등급표에도 내부 잠정 진단이라는 구분이 사라졌다. 실제 사업 성과, 증빙 신뢰도, 평가 시점을 분리한 정책을 보고서가 오해하게 만드는 문제다.
- 보고서 일부 경로는 PDM 원문을 파일명에 “최신”이 있는지에 따라 우선하거나 `LEFT JOIN`으로 불러왔다. 이후 전용 PDM 교체나 일반 업로드의 과거 PDM 모델이 존재할 때 화면의 현재 기준과 보고서의 설계 기준이 달라질 여지가 있었다.

## 수정

- 저장된 질문별 `scoring_trace.assessment_basis`를 보고서 컨텍스트에 전파한다. 점수나 근거는 재계산하지 않는다.
- 신규 정책의 등급표 총점·등급에는 `(잠정)`을 표시한다. 요약·결론·기준별 본문에는 현재 등록 자료에 따른 내부 진단이며 기관의 공식 확정평가가 아니라는 안내를 보존한다. 자료 부족으로 보류된 점수는 그대로 보류한다.
- 작성 프롬프트와 오류 재검토 문구도 공식 확정판정의 생성을 강제하지 않는다. HWPX 변환 시에도 같은 정책을 적용한다.
- 보고서 근거 문서, 작성 컨텍스트, HWPX 원문 셀은 완료된 활성 전용 PDM 문서와 연결된 최신 모델을 사용한다. 일반 자료의 파일명은 기준 PDM 선정 조건이 아니다.
- 독립 행사들을 합산한 성과는 대표 문서만 남기지 않고 모든 지원 문서 ID, 행사일, 집계 근거와 범위, 재검토 필요 여부를 보고서 컨텍스트에 보존한다. 대표 문서의 단일 행사 인용이 합계 수치를 직접 진술한 것으로 해석하지 않도록 한다.

## 검증

- 보고서·HWPX 관련 테스트 **258개 및 하위 사례 54개 통과**.
- 신규 회귀 검사: 잠정정책과 저장된 수치 보존, 원본 평가 불변, 내부 원문 중복 전송 제거, 등급표 HWPX 준비 과정의 잠정 표기 보존, 보류 점수 유지, 결론의 공식 확정 오표기 방지, 안내 중복 방지.
- 테스트는 외부 AI 키가 없는 격리 QA 컨테이너의 합성 자료로 실행했다. 운영 데이터나 평가 결과를 수동 변경하지 않았다.
- 집계 실적의 모든 근거·합계 보존 추가 검사: 성과 보고서 테스트 7개 통과. 신규 잠정정책과 기존 저장등급 검증의 양립 검사: 품질 방어·평가성격 테스트 28개 및 하위 사례 2개 통과.

## 종합점수 판정보류의 본문 검증 추가

운영 DAC 중 일부 기준이 `null`인 결과를 검토하면서, 등급표·HWPX 컨텍스트는 판정보류를 유지해도 결론 본문의 임의 총점은 차단하지 않음을 재현했다. `[3, 3, 2.7, 1, null]`에서 AI가 작성한 `9.7/20점·KOICA C등급`이 보류 안내와 함께 남고 숫자 검증을 통과할 수 있었다.

`report_score_validation.py`는 저장된 전체·기준 점수가 보류일 때 현재 점수·등급을 임의로 확정한 주장을 검출한다. 기존 hard validation에 연결하여 작성 후 검토·복구·내보내기 준비 검사를 공통 적용한다. 일반 교정 최대 3회와 복구 교정 최대 2회의 기존 한도를 유지하며, 해결하지 못한 본문은 성공으로 저장하지 않는다. 수치나 사실을 자동 삭제해 통과시키지 않는다.

명시적으로 구분한 과거 평가와 루브릭 예시, 1~4점 척도 설명, 유효한 하위 질문 점수는 허용한다. 같은 문단에 과거 점수와 현재 임의 점수를 섞거나 별도 보류 고지를 붙인 경우도 현재 주장은 차단한다. 문장 패턴 검사는 자연어 의미 전체를 보증하지 않으므로 실제 생성 내용에 대한 독립 비교와 화면 검토를 병행한다.

보고서 판정보류·평가성격·품질 방어 회귀 **53개 및 하위 사례 2개 통과**. 임의 숫자·등급의 검출, 구조화 셀의 0점 대체 방지, 문맥 예외, 교정 후 재검증 및 유한 재시도 종료를 포함한다.

## 운영 검증 완료 기준

1. 최신 성과지표·DAC 실행 완료 후 `POST /api/v2/report/generate-all`을 통해 새 평가를 반영한다.
2. 27개 섹션 완료와 최신 `input_snapshot`을 확인한다. 같은 입력의 일부 실패만 `generation/{id}/resume`으로 재개한다.
3. `POST /api/v2/report/exports` 완료 후 `layout_contract.ok`, `semantic_coverage.ok`, `project_identity_validation`, `rhwp_toc_verified` 및 실제 미리보기의 표지·목차·등급표·성과표·긴 표 쪽 넘김을 확인한다.
4. rHWP·kordoc 검증과 한컴 프로그램 검증을 구분한다. 한컴에서 열어보지 않은 결과를 한컴 확인 완료라고 기록하지 않는다.
