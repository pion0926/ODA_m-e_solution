# rHWP 표 본문이 쪽 경계를 넘었는데 내보내기가 완료되는 문제

상태: 서버 최종 렌더 검증에 실제 좌표 검사를 추가했다. 표 조판 자체의 수정은 별도 레이아웃 이슈에서 다룬다.

## 원인

기존 rHWP 최종 검사는 SVG의 `textContent`와 목차 목적지·쪽번호를 확인했다. SVG는 잘린 글자를 DOM에 그대로 보관하므로 텍스트가 존재한다는 사실만으로 사용자가 전체 글자를 볼 수 있음을 입증할 수 없다. 렌더러 자체 알림이 없어도 표 셀과 본문이 용지 바깥으로 나갈 수 있었다.

실제 60쪽 파일에서 5쪽의 표 셀 하단이 용지 높이 약 1122.5를 넘어 1235~1255까지 생성되었다. 기존 검사에는 이 좌표를 대조하는 단계가 없었다.

## 수정

- `rhwp_geometry.py`가 서버의 격리 브라우저에서 각 SVG의 실제 글자 `getBBox()`와 좌표 변환을 읽는다. 클리핑 전 전체 글자 경계를 용지·셀 clipPath와 비교한다.
- 표 안의 글자가 쪽 하단의 실제 쪽번호 영역에 진입하는 경우도 검출한다. 일반 머리말·바닥글을 임의의 여백 기준으로 오류 처리하지 않는다.
- 투명한 선택용 글자·빈 셀은 제외하고, 좌표 반올림 및 글꼴 미세 차이에 2 SVG 단위의 허용 오차를 둔다. 형식을 알 수 없는 표 clipPath는 검증 완료로 주장하지 않는다.
- 목차 쪽수가 최종 안정화된 정확한 파일에서 geometry 검증까지 통과해야 완료한다. 누락된 geometry 증명이나 경계 이탈이 있으면 구체적인 페이지와 유형으로 실패하며, 원문을 잘라 성공 처리하지 않는다.
- 선언한 `page_count`와 실제 검사 배열의 길이, 정수 페이지 번호 `1..N`의 순서를 대조한다. 누락·중복·역순·잘못된 번호나 행 형식은 정상 페이지로 대체하여 통과시키지 않는다.
- 오류 기록에는 페이지·셀 ID·좌표만 남기며 원문 내용은 포함하지 않는다. 프롬프트·모델·평가 입력 지문과 운영 DB를 변경하지 않는다.

## 검증 범위와 한계

실제 저장 SVG 60쪽을 오프라인 Chromium에서 검사하여 문제의 5쪽만 검출하고 정상 59쪽은 통과했다. 합성 회귀는 정상 머리말·바닥글, 변환된 셀 좌표, 셀 내부 잘림, 쪽 밖으로 이어진 표, 바닥글 침범, 투명 프록시, 표 밖 일반 글자 이탈과 최종 완료 차단을 포함한다. 전체 페이지 누락·중복 계약을 포함한 실제 Chromium 합성 검사와 보고서 최종화·내보내기 최신성 회귀 43개 및 하위 검증 2개를 통과했다.

이 검사는 글자·표 경계의 가시성을 확인한다. 문장의 의미·표 디자인·제목과 다음 내용 사이의 편집 품질까지 자동 보증하는 검사가 아니며 최종 화면 검토는 계속 필요하다.
