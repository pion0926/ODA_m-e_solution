# 성과 목표를 실적과 같은 보고 범위에서 선택

상태: 코드·회귀·저장된 운영 결과의 읽기 전용 재계산 확인 완료. 배포와 실제 결과 저장은 운영 흐름 검증에서 별도 수행한다.

## 원인

성과 증분 반영에서 실제값의 `최신 기준일 → 같은 날 높은 수치` 정책을 목표에도 적용했다. 당해 보고서의 목표 10명·실적 6명에 다른 미래 계획의 목표 20명이 함께 있으면 목표 20명과 달성률 30%를 선택할 수 있었다. 두 목표의 숫자가 직접 입증돼도 적용할 보고 범위가 다르므로 잘못된 비교다.

또한 `80%`와 `95% 이상` 같은 목표 후보는 수치/정성값 혼합으로 처리됐다. 후자의 조건을 없애서 숫자로 만들거나 더 높은 목표를 자동 선택해서는 안 된다.

## 수정

- 실제값을 먼저 선택한 후 목표를 결정한다.
- 공식 PDM에 명시된 목표가 우선한다.
- 공식 목표가 없으면 선택 실제값과 같은 원문 행의 목표, 그다음 같은 문서·호환 기간의 목표를 우선한다.
- 같은 문서에서도 미래 기간 목표는 과거 실적에 소급 적용하지 않는다. 같은 범위 안에서도 후보 값이 다르면 확인 필요로 남긴다.
- 실제값과 대응하는 근거가 없으면 참고 목표들이 동일할 때만 합의된 값을 표시한다. 서로 다른 목표가 남으면 빈 목표와 확인 필요 상태를 유지하며, 모든 후보의 출처를 보존한다.
- `이상·이하·초과·미만` 조건은 그대로 보존한다. 조건부 목표를 단순한 확정 숫자로 바꾸어 달성률을 계산하지 않는다.
- `target-selection-v2-actual-context`로 선택 정책을 추적한다. 과거 목표 선택은 사용자의 명시적 분석 실행 시 기존 문서×지표 측정 결과를 재사용해 재정리하며, 이를 위해 원문을 다시 AI에 보내지 않는다.

## 검증

- 목표 10명·실적 6명과 다른 미래 계획 20명 → 목표 10명·실적 6명·60%.
- 공식 PDM 목표가 별도로 있으면 보고 목표보다 우선.
- 같은 문서의 다른 연도 목표, 같은 보고 범위의 충돌, 실제값 없는 목표 충돌, 조건부 목표 보존, 숫자 표기만 다른 동일 목표, 정책 재정리에 측정 AI 호출 없음 회귀 추가.
- 관련 백엔드 96 tests·20 subtests 통과.
- 저장된 운영 결과를 읽기 전용으로 재계산하여 강사 지표 10명/6명/60%, 합동훈련 3회/1회/33.3%를 확인했다. 실제값이 없고 목표가 여러 개 남은 합격률 지표는 목표 확인 필요 상태를 유지했다. 이 확인 과정은 운영 DB·캐시를 변경하거나 외부 AI를 호출하지 않았다.
