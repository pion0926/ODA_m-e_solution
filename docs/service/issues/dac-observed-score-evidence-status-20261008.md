# 증빙 확보율 때문에 확인된 수행성과 점수가 사라지는 문제

## 원인

세부항목의 관측 성과로 기본점수를 산정한 뒤, 증빙 확보율·신뢰도 또는 일부 근거 충돌 상태가 정해진 문턱을 넘지 못하면 질문 점수를 `null`로 바꾸었다. 기준별 평균은 질문 하나라도 `null`이면 전체 점수를 보류했다. 이 경로는 확인된 수행 수준과 자료의 완전성을 다시 결합하여, 실제 관측된 성과의 잠정점수까지 없앴다.

## 수정

- `odame-contextual-2.1.20261008`은 관측 성과가 있는 질문의 기본점수와 실제 부정적 사실의 상한을 적용해 잠정점수를 보존한다.
- 증빙 확보율·신뢰도·미해결 충돌은 `evidence_status`, `confidence`, 세부 한계와 보완과제로 구분한다. 질문의 점수 상태는 `proposed`로 유지한다.
- 충돌·미확인·목표시점 미도래 항목은 관측 평균에 0이나 성공값으로 넣지 않는다. 확인된 다른 항목으로 판단하며, 직접 확인된 실패·미달·피해는 기존 감점과 상한을 유지한다.
- 모든 항목에 관측 근거가 없으면 임의 0점·2점을 만들지 않는다. 이번 변경은 관측된 수행성과가 증빙 상태 때문에 보류로 전파되는 문제를 해결한다.
- 최고 4점의 전체 충족·필수 근거 요건은 유지한다. 일부 관측만으로 사업 전체 성과를 확정하지 않는다.
- 사실 판정 프롬프트는 구체적으로 확인된 질적 수행성과와 증빙 자료 부족을 분리하도록 보강한다. 활동·산출물 수량을 Outcome 달성률로 바꾸지는 않는다.

루브릭과 판정 프롬프트 버전을 함께 변경하여 이전 판정을 정상 평가 API에서 다시 검토하게 한다. 등록 원문 추출 규칙은 변경하지 않는다. 기존 DB·보고서 내용에 수동 점수 보정은 하지 않는다.

보고서의 초안·품질 검토·복구 프롬프트에도 숫자 점수를 증빙 상태와 구분하도록 명시했다. 저장된 숫자 점수를 현재 기준 전체의 보류로 바꾸는 서술과 등급표 값은 검증 후 제한된 재작성 대상으로 처리한다. 과거 평가의 보류, 추가 검증의 보류, 실제 미관측 하위 질문은 기준 전체 점수와 구분하여 허용한다.

점수 정책만 달라졌을 때 기존 원문 사실까지 다시 추출하지 않도록 추출 계약을 분리했다. 실제 질문·상태·프롬프트·스키마·추출 및 검증 코드·청크 파라미터가 정확히 같은 검증된 두 정책 버전만 기존 추출 식별자를 공유한다. 새 질문 판정은 새 정책으로 다시 수행한다. 원문·파일 SHA·문서 역할·모델·추출 계약 변경은 재사용하지 않으며 확장된 검토 범위는 누락된 구간만 추출한다.

원문 추출 캐시가 점수 루브릭 전체의 지문을 사용하여 점수 안내만 바뀌어도 모든 원문을 다시 추출하는 문제도 분리했다. 두 검토된 정책 버전은 질문·상태 정의, 실제 추출 프롬프트·스키마, 원문 조각·인용 검증·비식별·범위 처리 구현과 파라미터의 지문이 정확히 일치할 때만 이전 원문 캐시 키를 사용한다. 알려지지 않은 버전이나 추출 조건 변경은 재사용하지 않는다. 질문 판정은 새 정책·프롬프트 지문으로 다시 수행한다.

완료 캐시의 빠른 반환도 원본 SHA와 산출물 여부가 포함된 재사용 식별자를 함께 확인한다. 본문 문자가 같더라도 원본이 교체되거나 문서 역할이 바뀌면 이전 원문 판정을 그대로 반환하지 않는다. 추출 구현 지문은 변경 불가능한 작업자 이미지의 코드에서 계산하고 프로세스 내에서 캐시하며, 정책 설명과 무관한 원문 처리 코드를 수정했을 때도 보수적으로 새 검토를 요구한다.

## 회귀

합성 두 관측 항목의 부분 수행과 세 미확인 항목, 낮은 신뢰도, 일부 충돌, 직접적인 실패, 전체 미확인·미도래를 구분해 검증한다. 보고서용 컨텍스트가 잠정점수와 `evidence_status`·신뢰도를 함께 보존하는지도 확인한다. 실제 재평가와 보고서 재생성은 별도 운영 절차로 수행한다.

실제 AI 요청 경계를 모의하여 초안·품질 검토·복구의 숫자와 `null` 전달을 확인한다. 등급표 바인딩, 현재 점수와 보류의 모순, 과거·부정·하위 질문 예외 및 유한 재작성도 검사한다. 이전 출시 알고리즘으로 독립 생성한 원문 캐시는 정책 변경에 추가 AI 호출 없이 재사용되며, 11종 추출 조건 변경은 재추출됨을 확인한다.

원문 캐시는 이전 출시 버전의 키 계산식을 독립 재구성한 합성 캐시로 검증한다. 정책만 바뀌면 외부 추출 호출이 없고, 질문·상태·프롬프트·스키마·처리 구현·청크 조건·원문·원본 SHA·문서 역할·모델 또는 미검증 버전이 바뀌면 재추출되는지 확인한다. 검토 범위만 넓어지면 기존 범위를 유지하고 새 원문 구간만 호출한다.
