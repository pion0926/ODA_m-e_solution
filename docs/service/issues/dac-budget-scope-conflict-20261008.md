# DAC 예산 비교 범위·근거 충돌 판정 오류

상태: 코드 수정 및 합성 회귀 검증 완료. 운영 결과는 정상 DAC 재실행으로 재판정하며 DB 점수·캐시를 수동 수정하지 않는다.

## 확인된 원인

2026-10-08 운영 DAC 11개 질문 완료 결과를 읽기 전용으로 검토했다. 효율성 두 질문의 1점 상한은 학생인건비·연구기자재 등 개별 비목의 150% 초과를 전체 사업 예산 초과로 적용한 결과였다. 기존 산식은 질문 구분, 전체 사업 범위, 측정 검증 실패, 중대한 부정 조건의 실제 충족 여부를 확인하지 않고 모든 예산·기간 비율에 상한을 적용했다. 실제 질문 판정은 전체 예산 초과를 미확인, 다른 효율성 질문의 중대 부정을 비해당으로 기록하고 있었다.

지속가능성 질문에서는 자체 예산 운영 확약과 별도 승인예산·집행자료의 미확인을 상충으로 판단했다. 후자는 원문의 명시적 부정 사실이 아닌 이전 AI의 검색용 finding인 경우가 있었다. 확약의 존재, 현재 준비 상황, 종료 후 운영실적과 증빙 신뢰도를 분리해야 한다.

## 수정

- 효율성 예산·기간 질문의 해당 항목에만 전체 사업 150% 상한을 적용한다. 비교 가능·기한 도래·정량 원문 검증·해당 항목 검증을 모두 통과해야 한다.
- `measurement_scope`와 `scope_quote`를 AI 스키마에 추가했다. 서버가 인용 연속 일치와 전체 사업 예산/기간 표식을 독립 검사한다. 비목·연차·개별 계약만 있는 인용이나 범위 미확인은 전체 사업으로 인정하지 않는다. 수치 관찰 자체는 보존한다.
- 승인·불가피성 확인된 전체 초과는 기존 2점 상한을 유지한다. 1점은 타당한 사유 없음이라는 중대한 부정 조건도 직접 확인되어야 한다. 승인자료 미첨부만으로 사유 없음을 추정하지 않는다.
- `conflicted`는 같은 사실·기간·대상/범위에 대해 동시에 참일 수 없는 원문 두 개에만 사용하도록 명시했다. 자료 부재·침묵과 긍정 사실을 충돌로 만들지 않으며, `finding`을 원문 주장으로 취급하지 않는다. 종료 후 미도래 성과와 현재 준비 상황도 구분한다.
- 점수 하한을 강제하거나 정규식으로 AI의 상태를 변경하지 않는다. 실제 부정 사실과 실제 원문 충돌은 계속 점수·보류에 반영한다.

## 캐시와 검증

판정 `PROMPT_VERSION`만 `dac-fact-judgement-v15-scope-conflict`로 변경했다. 전체 평가 재사용과 질문 판정 digest는 무효화되지만, 사실 추출 `RULE_DIGEST`는 유지한다(`562164e5bf9722da9f882a0c96cf877dbd46774684ec0a816cf0616b48daa812`). 같은 모델·문서·범위의 기존 원문 사실 캐시를 재사용할 수 있다.

근거 선별 캐시는 선별 버전·모델·질문 정의·사실 목록으로 별도 계산한다. `load_question_candidates`가 같은 프로젝트의 최근 12개 완료/실패 실행에서 선별 체크포인트를 가져오며 전체 평가 fingerprint로 제한하지 않는다. 판정 프롬프트만 바뀐 정상 재실행에서 기존 선별 결과도 재사용하는 회귀를 추가했다.

회귀는 11개 질문 간 상한 누출, 승인 확인/미확인, 실제 중대 초과, 무효 숫자, 미도래·비교 불가, 범위 오표기, 한국어·영어 전체 범위, 미지원 범위, 버전별 재사용을 검사한다. 분리된 일회용 QA 컨테이너에서 `test_dac*.py`와 `test_stability_20260924.py` 188개 및 하위 검증 51개를 통과했다. 외부 AI와 운영 DB를 호출하지 않았다. 실제 운영 재판정의 정확성과 화면은 배포 후 별도로 검토한다.
