# DAC 신규 자료 등록 후 질문 전체 재판정과 부분 원문 실패 전파

## 원인

완료 질문은 실행 내부 `question_checkpoints`에 저장했지만, 전체 자료 지문이 같은 실패 실행을 복구할 때만 재사용했다. 신규 자료를 추가하면 전체 자료 지문이 달라져 완료한 질문도 다시 요청했다. 질문별 프롬프트에는 관련 없는 전체 문서 목록도 들어갔고 업로드 순번 기반 문서 참조가 근거 ID에 포함되어, 무관한 문서 추가·제외가 질문 지문을 바꿀 수 있었다.

또한 한 문서의 질문 A 검토 구간이 실패하면 같은 기준의 질문 B 검토를 완료했어도 기준 전체를 중단했다.

## 변경

- 프로젝트별 최근 완료·실패 실행의 질문 후보를 읽고, **질문별 입력이 정확히 같은 결과만** 현재 규칙으로 재검증해 사용한다. SQL의 프로젝트 조건과 기존 RLS를 함께 유지한다.
- 질문에 실제로 선택한 문서·검토 범위만 문서 검토 목록에 넣는다. 근거를 찾지 못한 검토 범위도 입력에 포함하여 자료 추가를 누락하지 않는다.
- 원문 해시·인용·선택 구간·파일명·질문 정의·루브릭·시스템 프롬프트·연동 모델·사업기간/평가일·제시된 PDM 현황이 바뀌면 재판정한다. 삭제·평가 제외·반대 근거 추가도 동일하다.
- 문서 참조는 업로드 순번 대신 문서 식별자에서 생성하며 질문의 근거 순서를 정규화한다.
- 재사용한 결과도 새 실행에 체크포인트와 원 실행 식별자를 남긴다. 전체 실행 재사용에서도 체크포인트를 보존한다.
- 질문 A의 원문 구간이 미완료여도, 질문 B의 선택 구간 전체를 검토했다면 B의 판정·체크포인트를 진행한다. 미완료 구간을 가진 질문은 점수로 확정하지 않는다.

## 검증

외부 AI 키 없는 격리 QA 컨테이너에서 DAC 및 공급자 회귀 **143개 + 51개 하위 사례 통과**.

- q1 자료 추가 시 q1만 AI 호출, q2 검증 후 재사용.
- 무관한 자료·업로드 순번 변경은 재사용 유지.
- 근거 없는 신규 검토 문서, 원문 교체, 범위 변경, 제외, 반대 증거는 해당 질문 갱신.
- 평가일·사업단계·PDM 현황/근거·모델·루브릭·프롬프트 변경 시 재판정.
- 캐시의 잘못된 인용을 그대로 복사하지 않고 재생성.
- 부분 원문 실패가 다른 완료 질문의 저장을 막지 않음.

실제 PostgreSQL JSONB 저장·프로젝트 범위·RLS 확인 진입점은 `tools/qa_dac_question_reuse.py`다. QA 전용 연결을 강제하며 합성 행은 트랜잭션 롤백한다. QA PostgreSQL에서 모델 바인딩과 정상 반복 실행을 포함한 6개 검증 모두 통과했고 합성행 롤백을 확인했다.

정상 `evaluation_runner._run_all` 경로의 반복 검증은 공급자 응답과 원문 추출만 합성 데이터로 대체하고 실제 SQL·문항 검증·저장 로직을 실행했다.

- 최초 실행에서 11문항·5개 기준을 저장했다.
- 같은 자료의 두 번째 실행은 이전 DAC 실행 ID·완료 시각·사전검토 revision이 바뀌어도 전체 실행을 재사용했다. 추가 AI 호출은 0건이고 11문항 체크포인트와 재사용 출처가 보존됐다.
- 전체 실행 재사용만 우회한 세 번째 실행에서도 질문 11개를 현재 근거로 다시 검증한 뒤 재사용했다. 같은 PDM 내용을 새 UUID·생성 시각으로 저장해도 추가 AI 호출은 0건이었다.
- 이 검증에서는 평가일·원문·매핑·PDM 의미가 동일하다. 실제 날짜·평가 시점 또는 지표 수치가 바뀌는 경우를 재사용 가능한 것으로 취급하지 않았다.

## 대기 모델 정책 및 사용자 안내

공통 작업 큐가 접수 당시 모델을 계속 사용하던 문제도 확인했다. 새 작업을 `queued → running`으로 가져오는 트랜잭션에서 프로젝트 모델을 읽고 공유 잠금으로 관리자 설정 변경과 실행 경계를 구분한다. 작업·실행 인자·모델 필드가 있는 접수 이력을 함께 갱신한다. 실행 중 모델은 다시 읽지 않으며 변경하지 않는다. 잘못된 모델은 다른 모델로 대체하지 않고 해당 작업만 실패로 표시한다.

보고서 재개의 완료 섹션은 기존 모델·본문을 유지하고, 새로 작성하는 섹션은 현재 프로젝트 모델을 따른다. 별도 `OPENROUTER_PRESENTATION_MODEL`을 사용하는 발표자료 전용 모델은 프로젝트 설정으로 조용히 바꾸지 않는다. 일반 평가 API에는 사용자별 일회성 모델 덮어쓰기 기능이 없다.

DAC 사전검토 화면에 질문 재사용 조건을 설명하고 AI 작업 트레이에 검증 완료/재사용 질문 수를 함께 표시한다.

모델 바인딩·큐·질문 재사용·프로젝트 모델 회귀 73개, 프런트 계약 테스트 18개 통과. 발표자료 전용 모델 유지, 지원하지 않는 모델의 실패 처리, 실행 중 모델 유지, 기존 보고서 초안의 모델 기록 보존을 포함한다.

## 경계

새 질문 지문 형식 적용 후 첫 평가는 기존 지문을 재사용하지 않는다. 이후 변경 없는 문항부터 재사용한다. 날짜가 바뀌면 목표 도래 여부를 다시 검토하고, PDM 보조 현황이 변경되면 모든 질문이 해당 현황을 참고하므로 안전하게 다시 판정한다. 점수를 임의로 유지하거나 자료의 미확인을 성공으로 바꾸지 않는다.

사업개요는 검증된 사업계획서 입력으로 별도 생성하며, 사업계획서 입력 전용 재사용 지문이 없어 현재는 DAC 새 실행에서 한 번 다시 생성할 수 있다. 이 최적화를 위해 임의로 과거 사업개요를 복사하지 않는다.
