# 동일 원본 신규 프로젝트 전체 흐름 검증

- 요청: 기존 knut과 같은 사업계획서·PDM·일반자료를 새 프로젝트와 새 계정에 업로드하여 처음부터 최종 HWPX까지 검증.
- 환경: 운영 `https://app.kodame.kr`, API/워커/웹 V2.4.16 배포.
- 신규 프로젝트: `교통대 신규 전체흐름 검증 2026-09-29`, `378f7335-45da-4e4a-965d-4aa4f6cdb1c5`.
- 신규 일반 계정: `knut.qa.20260929`, 신규 프로젝트만 배정. 임의 발급 비밀번호는 git 제외 로컬 설정에 보관.
- 모델: 기존 knut과 동일한 `openai/gpt-5.6-luna`, 관리자 배정 API 및 실제 문서 작업 모델 확인.
- 데이터: knut의 활성 원본 63건, 137,067,547바이트. 63건 모두 다운로드 후 SHA256 일치. 분석·평가 캐시는 복사하지 않음.

## 진행 기록

1. 신규 프로젝트 생성 중 공급자 공개 모델 목록 부분 응답으로 모델 배정 422 재현. [이슈 21](issues/20260929-21-model-catalog-partial-response.md)로 정리하고 테스트 27개 및 개발서버 실연결 검증 후 운영 V2.4.15 배포. 신규 계정 생성과 luna 배정 완료.
2. 신규 계정 브라우저 로그인: 빈 프로젝트, 지표/평가/보고서 없음 확인.
3. 사업계획서 `사업기본자료_5차년도 사업계획서_2026-06-23_교통대.pdf` 업로드: `a470a404-6c96-42ac-9a30-a7aa58570e14`.
4. PDM `DAC_PDM_최신 PDM_2026-06-23_교통대.pdf` 업로드: `4940485e-d6d7-4d8b-a997-4ab3fa5c0bb7`.
5. 기준 문서 분석 중 일반 업로드 잠금과 AI 작업 트레이 자동 표시 확인. 두 기준 문서 모두 최초 시도에 분석 완료.
6. 사업 기본정보 출처는 신규 사업계획서 ID. 사업명은 `우즈베키스탄 응급구조학과 구축 및 지역사회 CPCR, MCI Triage 교육 프로그램`, 사업책임자 신동민, 사업 수행기관 국립한국교통대학교로 확인. PDM 14개 지표 추출.
7. 일반자료 61건 브라우저 업로드 완료. 서버에서 일반 문서 4건 동시 처리와 luna 모델 확인. 최신 PDM과 동일한 일반 문서 1건은 자동 중복 제외.
8. 새 계정으로 knut 원본 다운로드를 시도하여 404 확인. 기존 프로젝트 접근 불가.
9. PDM 원안이 제외 근거 검증 실패로 포함됨을 발견. [이슈 22](issues/20260929-22-alternate-pdm-screening-recheck.md) 보완 및 25개+6 subtest 통과. 동일 원문의 별도 luna 검증은 정상 제외 판정을 얻었으나 문서 상태에 수동 적용하지 않았다. 실제 신규 코드 재처리는 토큰 한도 확대 후 진행해야 한다.
10. 토큰 보호 한도 도달: 전체 63건 중 36건 완료(중복 제외 1건 포함), 27건 실패. 27건 모두 동일한 `AI 사용 한도(tokens)` 오류이며 파싱/원문 검증/공급자 생성 오류는 아님. 최신 신규 프로젝트 확인 사용량 2,986,425토큰, $0.93599856. 보호 한도 집계는 미확정 요청의 사전 예약량도 포함한다.
11. 기존 knut 약 26,952,019토큰+신규 요청 예약량으로 API 키별 최근 24시간 기본 30,000,000 한도가 소진됨. 토큰 한도만 임시 50,000,000으로 늘리고 전체 $100/일·계정 $60/일·작업 $30 비용 한도는 유지하는 승인을 요청했다. **승인 전 한도 미변경.**
12. 성과지표 분석, DAC 평가, 27개 보고서 생성, 최종 HWPX 검증은 아직 미실행. 한도 승인/갱신 후 중단 문서를 재요청하고 원안 재처리부터 이어가야 한다.

## 사용량 한도 해제 후 재개

- 사용자가 임시 확대 대신 자체 사용량 한도 해제를 요청했다. V2.4.17로 개발·운영에 영구 반영했다. 운영 API 및 5개 워커 모두 사용량 제한 off, 사용량 기록 on, 전체 동시 요청 4개, 전체 작업시간 상한 off 확인.
- 기존 계정 발급 시 저장한 비밀번호로 재개 로그인 요청 시 401 반환. 계정과 프로젝트는 활성 상태이며 계정 updated_at은 2026-09-29 08:32:52 UTC로 생성 이후 변경되어 있다. 비밀번호를 재설정하거나 다른 값으로 추측 시도하지 않았다. 재개 스크립트는 인증 전에 종료되어 문서 재시도를 아직 실행하지 않았다.

## 추가 관찰

- 처음 새 브라우저 탭에서 정적 자산 로드가 일부 실패하여 접속 확인 화면이 남았고, 새로고침 후 정상 로드됨. 외부 shell을 받지 못하면 복구 처리기도 없던 점을 수정. 전송 실패의 네트워크 원인은 미확정.
- 좁은 우측 브라우저 폭에서 로그아웃 버튼이 숨겨지던 문제는 상단 버튼으로 보완. 개발 800px에서 실제 로그아웃 완료 확인, 기본 화면 크기로 복구. [이슈 23](issues/20260929-23-startup-recovery-compact-signout.md).
