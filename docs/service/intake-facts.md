# 문서 등록 시 평가 준비 사실 추출

일반 자료는 전체 추출 원문을 28,000자 구간(1,000자 중첩)으로 읽는다.
등록된 사업계획서와 PDM, DAC 세부질문을 맥락으로 사용한다.
기존 기본 분석/슬롯 매핑을 유지하며 foundation matching 호출에서 사실을 함께 추출한다.

`analysis.registration_facts`에 다음을 저장한다.

- 버전, 입력 텍스트 해시, 전체/일부 검토 범위
- 구간별 사업 맥락 설명 및 통합 문서 역할 요약
- 사실별 종류, 수치, 단위, 기간, 대상, PDM 지표 ID와 DAC 세부질문 ID
- 검증된 연속 원문, 비식별 처리된 구간 기준 위치, 제외한 후보 수

원문 인용이나 값 검증에 실패한 후보만 제외한다. 이로 인해 문서 등록을 실패시키지 않는다.
AI 호출/출력 생성 실패는 기존 재시도 처리에 따른다.
산출물 등록은 기존 표본 검토 범위를 유지하고 교재 내 수치를 사업 실적으로 저장하지 않는다.

성과 분석은 등록 사실을 원문 재검토 후보로 전달받는다. DAC 평가 준비는 해당 질문에 연결된
사실의 원문을 이용해 검토 구간을 찾는다. 업로드 시 달성도나 DAC 점수를 확정하지 않는다.

업로드 목록에는 사업계획서 연결 슬롯을 표시하거나 연결 수에 포함하지 않는다.
사업계획서 관련성은 사업 맥락 요약에 활용한다. 요약은 기본 접힘이고 새로 저장한 사실 수를 표시한다.

기존 문서를 일괄 재분석하거나 운영 데이터를 변경하는 마이그레이션은 포함하지 않는다.
새 등록 및 명시적 재처리부터 적용된다. 기준 문서 재매칭 시에는 사실 및 요약도 함께 갱신한다.

검증: intake facts, evidence matching, intake triage/failure isolation, DAC review,
PDM evidence/targets 회귀 테스트. 실제 문서를 외부 모델에 재전송하는 검증은 하지 않았다.
