# 사업계획서 분석 역할 분리 및 원문 참조

운영 V2.2.12 수정 사항:

- 사업계획서 업로드는 PDM 원본 판단과 PDM 셀 추출 스키마를 사용하지 않는다.
- 사업계획서 여부 자체는 본문으로 확인한다. 단순 보고서나 회의록을 사업계획서로 무조건 승인하지 않는다.
- 분류 근거와 DAC 매칭 근거는 AI가 인용문을 다시 쓰지 않고 서버가 제공한 원문 구간 ID를 선택한다. 서버가 정확한 원문을 복사한다.
- 허용된 ID를 스키마와 서버 양쪽에서 검증하며, 잘못된 ID는 최대 3회 수정 후 사업계획서 근거 오류로 처리한다. PDM 오류로 표시하지 않는다.
- 전체 문서 구간을 검토하되 부록 구간이 단독으로 사업계획서 역할을 입증할 필요는 없다.
- 일반 문서 및 PDM 분류의 기존 검증은 유지한다.
- `test_plan_source_references`, `test_content_classification`, `test_foundation_upload`, `test_foundation_routing`, `test_dac_resilience`: 34개 통과.

사업개요는 최신 활성 사업계획서만 사용하며, PDM 업로드는 사업개요를 생성하지 않는다(V2.2.11). 이전 PDM 기반 개요는 현재 사업개요 조회에서 제외하고 이력은 보존한다.
