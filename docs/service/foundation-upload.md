# 사업 기준 문서 업로드 (개발, 2026-09-24)

- 자료 업로드 화면 상단에서 사업계획서와 PDM을 각각 한 파일씩 등록한다.
- 두 문서의 최신 접수 건이 모두 `completed`일 때 일반 증빙 업로드가 열린다. API에서도 같은 조건을 검사한다.
- 교체 시 전체 사업 구성 변경을 확인한다. 요청에는 확인한 이전 문서 ID를 전달하고 서버에서 다시 비교한다.
- 교체본의 문서 분석이 성공하면 이전 같은 역할 문서를 `superseded_at`으로 보존한다. 이전 원본의 다운로드 링크는 유지한다.
- 현재 자료 조회는 RLS를 따르는 `active_intake_documents` 뷰를 사용해 교체 이력을 제외한다.
- PDM 갱신 및 사업 개요 재생성을 시도한다. 기존 평가·보고서 본문은 유지하며 자료 변경에 따른 최신성 검사로 재평가·재생성을 안내한다.
- 일반 증빙은 원본 저장·텍스트 추출·AI 기본 분석과 파일별 매칭까지만 수행한다. 사업계획서/PDM 역할 판단과 PDM 셀 추출 요청은 하지 않는다.
- `analysis.evidence_matches`에 사업계획서 항목·PDM 지표·DAC 증빙 슬롯·보고서 섹션을 독립적인 배열로 저장한다. 기준 문서 ID/해시, 신뢰도, 판단 이유와 원문 근거를 보존한다. 사업계획서 대조에는 추출 본문 앞 12만 자를, PDM 대조에는 등록 지표 전체를 사용한다. 일반 자료의 추출 본문은 분할하여 매칭한다.
- 일반 업로드에서 DAC 원문 근거 분석·성과 측정·리스크 분석·사업 개요 갱신은 실행하지 않는다. 사업계획서·PDM 전용 업로드의 분석과 자동 갱신 경로는 유지한다.
- 성과지표 모니터링의 ‘성과지표 분석’은 먼저 분석 개요와 지표별 문서 매핑 표를 연다. 기존 문서의 매핑 추가·해제와 새 일반 자료 업로드를 지원하고, 기본 분석이 완료될 때까지 실행을 제한한다.
- ‘분석 실행’에서 확인한 문서 목록만 해당 지표의 성과·리스크 분석에 사용하고 매핑을 저장한다. 검토 중 문서나 PDM이 변경되면 다시 확인하도록 제한한다. 화면을 열거나 닫는 것만으로는 분석하지 않는다.
- DAC 평가진단의 ‘DAC 근거 분석·평가’에서 원문 근거 분석과 점수 산정을 수행한다. PDM은 저장된 상태를 읽고 미실행/최신/미반영 여부를 전달하며, 성과 모니터링을 다시 계산하지 않는다.
- 최초 마이그레이션은 기존 분석에서 확인된 최신 PDM 및 별도 사업계획서를 기준 문서로 채택한다. 하나의 기존 파일을 두 역할로 중복 채택하지 않는다. 미확보 역할은 전용 영역에서 등록한다.

검증: `test_foundation_upload`, 기존 문서 분류·최신성·DAC 분석 테스트 총 37개 통과. `tools/qa_foundation_upload.py`는 임시 DB와 대체 AI 응답으로 API 제한, 교체 경쟁, 실패·재시도, 원본 보존, 중복 처리, 마이그레이션 재실행, 테넌트 격리 및 실제 브라우저 취소·승인을 검증한다. 실문서 외부 AI 호출은 이 검증에 포함하지 않는다.
