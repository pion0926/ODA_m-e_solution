# PDM·DAC 갱신 안정성 개선 — 2026-09-24

## 변경 사항

1. 사업개요 출력은 공통 OpenRouter 경로를 사용한다. 17개 필드와 conflicts에 대해 필수 키, 데이터 형식, 허용 문서 참조, 빈값 규칙, 충돌 근거를 검증한다. 프롬프트에 JSON escaping, 중복 키·NaN·Infinity 금지, 배열/숫자/불리언 규칙, 필수 필드 유지, 짧고 완전한 응답 계약을 명시한다. 잘린 출력·잘못된 JSON·스키마/참조 오류는 최대 3회 다시 요청한다.
2. 기본 요청은 strict JSON Schema와 require_parameters를 사용한다. 공급자가 형식 미지원 또는 스키마 컴파일 크기 제한을 명시한 경우에만 동일 모델의 JSON 모드로 요청한다. 이 경우에도 원래 스키마를 프롬프트에 포함하고 서버의 동일한 검증을 통과해야 한다. 다른 모델로 자동 전환하지 않는다. 인증·결제·거절은 형식 오류와 구분한다. 일시적인 네트워크·429·5xx는 제한된 지연 재시도를 사용한다.
3. DAC 질문마다 증빙을 E/T 단축 참조로 제시하고 PDM ID는 별도 허용 목록으로 제한한다. PDM 보조자료의 문서 UUID를 인용 ID로 잘못 복사하지 않도록 모델 입력에서 제거한다. 반환 참조는 실제 원문 ID에 정확히 역매핑한 뒤 점수 엔진에서 검증한다. 존재하지 않는 ID를 임의의 문서에 연결하거나 누락 근거를 생성하지 않는다.
4. 검증된 질문 원응답과 입력 해시를 evaluation_runs.input_snapshot에 매 질문마다 저장한다. 재평가 요청 시 동일 프로젝트의 실패 기록에서 자료·분류·사업개요·PDM·모델·루브릭/프롬프트 버전·평가기준일이 일치할 때만 복구한다. 복구된 질문도 다시 검증한다. 변경이 있으면 새 평가를 수행한다. 이전 실패 기록과 완료된 기준 결과는 삭제하지 않는다. 구버전 실패 기록은 안전한 체크포인트가 없으므로 자동 재사용하지 않는다.
5. PDM 수동 갱신은 DB에 queued/running/completed/partial/failed 상태를 남기는 백그라운드 작업으로 전환했다. 동일 프로젝트의 진행 중 요청은 하나로 합치고 DAC와 동시 실행을 제한한다. PDM 스냅샷과 완료 영수증은 같은 트랜잭션에서 저장한다. 서버 재시작 시 남은 실행 기록은 실패로 정리하되 기존 PDM은 보존한다.
6. 웹 화면은 PDM 상태를 서버에서 주기적으로 확인한다. 저장 후 목록·번역 조회 실패는 작업 실패로 바꾸지 않고 ‘저장 완료 · 화면 조회 지연’으로 구분하며 화면 조회만 재시도한다. 페이지를 다시 열어도 상태를 복구한다. 일부 AI 분석만 미완료인 경우 partial로 구분한다.
7. 동시 진행된 내용 기반 문서 분류 변경과의 호환성을 보완했다. 새로운 분류 정보가 없는 기존 문서에 한해, DB에 이미 검증·저장된 정확한 source_document_id와 source_cells를 이어 사용한다. 파일명 추정이나 임의 대체를 하지 않고, 새 분류에서 PDM이 아니라고 판정한 문서는 재사용하지 않는다.

## 검증 기록

- 관련 회귀 테스트 128개 통과. 이후 Claude 크기 제한·비정상 수치 보강을 포함한 출력 경로 24개 통과.
- 신규 내용 분류와 기존 PDM 호환 테스트 12개 통과.
- 별도 UUID 테스트 DB에서 10개 통합 항목 통과: 중복 갱신 억제, 테넌트 격리, 완료 상태 복구, 트랜잭션 롤백, DAC 5개 질문 완료 후 강제 실패, 실패 질문부터 재개, 사업개요/PDM 재사용, 전체 11개 질문 완료, 변경 입력 복구 금지.
- 프런트엔드: 저장 성공 후 화면 실패, 새로고침 복구, 접수 응답 손실, partial 상태 구분 검증.
- 합성 문서로 실제 OpenRouter 사업개요 생성: google/gemini-3.5-flash-lite, openai/gpt-5.6-luna, anthropic/claude-haiku-4.5 통과. Claude에서는 실제 strict schema 컴파일 크기 오류를 확인하고 동일 모델 JSON 모드 + 로컬 스키마 검증으로 통과했다. 전체 공급자의 모든 모델·경로를 실행 검증한 것은 아니다.
- 운영 도메인 HTML/새 스크립트 HTTP 200, 실제 Chromium에서 KODAME_LIVE_READY=true, ServicePdmRefresh 로드, 페이지 JavaScript 오류 없음.
