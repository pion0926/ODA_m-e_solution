# 문서 추가 이후 증분 처리와 최신성 경계 최종 검토

운영 v2.4.29 실행 중 코드와 저장 정책을 읽기 전용으로 확인했다. 운영 결과·문서·캐시를 변경하거나 외부 AI를 추가 호출하지 않았다. 아래의 소스 경로는 동작 근거이며, 모든 동시성 시나리오를 운영에서 강제로 재현했다는 의미는 아니다.

## 확인한 경로

| 상황 | 현재 동작 및 보존 범위 |
| --- | --- |
| 신규 일반 문서 | 원본·추출·문서 역할·등록 사실·목적 매핑을 먼저 저장한다. 명시적인 성과 분석 시 신규 문서×지표만 추출하고 유효한 과거 조합을 재사용한다. |
| 성과 신규 수동 매핑 | 완료·활성 문서만 선택할 수 있다. 같은 문서를 다른 지표에 처음 연결하면 별도 조합이다. 기존 연결 조합은 신규 실행에서 제외한다. |
| 과거 미연결 조합 복원 | 감사에서 복원이 막힌 버그를 확인해 별도 수정했다. `issues/performance-manual-mapping-restore-20261008.md` 참조. 명시 선택한 유효한 과거 조합은 원문 추출 없이 재사용한다. |
| 평가 대상 제외 | 진행 작업이 없고 문서 버전이 일치할 때만 변경한다. 제외 문서는 평가 대상 view에서 빠지며 성과 API의 기존 실적도 유효한 출처로 다시 걸러진다. 재포함은 등록 분석을 거친다. |
| 사업계획서/PDM 교체 | 진행 중인 평가·보고서 작업과 중복 교체를 차단한다. 교체 영향·사유를 확인한다. 새 기준 문서 분석 성공 후 과거 기준을 보관 상태로 전환한다. PDM 기준 ID 변경은 과거 조합 캐시 재사용을 무효화한다. |
| 동일 성과 입력 재실행 | 신규 조합·목표/연결 변경이 없으면 409로 안내하며 기존 결과를 유지한다. 재검증 버전이 필요한 조합은 새 검토 대상으로 취급한다. |
| DAC 재평가 | 질문별 문서·선택 구간을 검토한다. 질문 입력·출처·모델·규칙이 같고 인용 재검증을 통과한 checkpoint는 재사용한다. 영향을 받은 질문은 재평가한다. 전체 입력이 동일하면 완료 평가를 재사용할 수 있다. |
| 보고서 재개 | 같은 입력의 실패·중단 작업은 유효한 완료 섹션을 보존한다. 자료·평가가 달라진 후에는 최신 보고서 작성이 필요하다. 오래된 섹션을 최신이라고 표시하지 않으며 최종 내보내기에서도 최신성을 확인한다. |

## 입력 변경과 실패 보존

일반 문서는 성과·DAC·보고서 작업 중에도 업로드할 수 있다. 실행 대상은 자동으로 계속 늘어나지 않는다. PDM은 시작과 저장 전 snapshot을 비교하며(`pdm_monitoring.py`), DAC는 저장 전 문서/분류/PDM fingerprint와 문서 snapshot을 비교한다(`evaluation_runner.py`). 변경 시 기존 결과를 승격하지 않고 최신 자료로 재실행하라는 오류를 작업 상태에 저장한다. `pdm_jobs.serialize` 및 평가 status API가 오류를 전달한다.

PDM의 완료된 문서별 추출 캐시는 최종 모델 저장 전 별도 연결로 저장된다(`pdm_evidence.py`). 모델·원문·지표·이전 평가 조건이 같으면 재사용할 수 있다. DAC 실패 처리도 `input_snapshot`을 지우지 않는다. 완료 질문·증빙 선택 checkpoint는 남고 다음 평가에서 정확한 입력과 인용을 확인한 후 재사용한다(`evaluation_recovery.py`, `dac_question_reuse.py`). 변경이 있는 모든 질문을 무조건 재사용하지는 않는다.

보고서 작성 중 입력이 변경되면 각 섹션의 snapshot과 최신성 검사가 이전/새 자료의 혼합을 최종 최신 보고서로 승인하지 않도록 한다. 다만 생성 작업 자체는 남은 섹션을 계속 처리하고 `completed`가 될 수 있다. 완료 상태는 모든 섹션의 최신성을 보증하지 않는다. `project_lifecycle.report_current`와 내보내기 API의 검사가 별도로 필요하며, 현재 내보내기는 최신 보고서가 아니면 409로 차단한다.

## 운영·성능 제한

- 자료를 지속 추가하면 이미 실행 중인 긴 평가가 종료 경계에서 입력 변경으로 중단될 수 있다. 이는 현재 확인한 데이터 혼합 방지 정책이며 서비스 전체 장애와 구분해야 한다. 재실행 시 조건이 같은 완료 근거를 재사용하되 신규 자료의 영향 범위는 다시 검토한다.
- PDM `refresh_pdm_model`은 트랜잭션 advisory lock을 위해 AI 실행 전체 동안 DB 연결 하나를 유지한다. 프로세스별 pool 상한은 8이며 분석 워커는 2개로 분리된다. 각 워커는 leadership 연결 하나도 보유하고 PDM 문서 분석은 최대 4개 병렬이다. 현재 구성에서 즉시 pool 고갈을 뜻하지 않지만 여러 장시간 작업과 보조 DB 조회가 겹치는 부하 시험은 별도로 필요하다. 업로드/DAC의 일반 AI 호출은 짧은 DB 연결 범위 밖에서 수행한다.
- 동일 입력 DAC 전체 재사용은 서버가 검증한 lineage를 통해 보고서 현재성을 보존하도록 별도 수정했다(`issues/report-freshness-on-dac-replay-20261008.md`). 문서·workflow·assessment fingerprint가 모두 동일한 whole-run replay에만 적용하며 실제 실행 ID는 보존한다. 실질 재평가·부분 질문 재사용·모델/평가일 변경에는 이 예외를 적용하지 않는다. 일반적인 섹션별 의미 비교로 모든 재작성 비용을 줄인 것은 아니다.
- 동일 실적의 다른 문서, 같은 날짜 여러 팀/세션, 기간·단위가 다른 값은 단순 합산하지 않는다. 명확한 구분 근거가 없으면 기존 검증값·집계 확인 필요를 유지한다. 책 원본 업로드만으로 배포 실적이나 교육 효과를 만들지 않는다.

추가로 확인한 현재 미연결 과거 조합의 수동 복원 버그는 위 별도 이슈로 수정·회귀 검증한다. 이 문서는 실제 오류와 의도된 보수적 제한을 구분하기 위한 QA 보충 기록이다.
