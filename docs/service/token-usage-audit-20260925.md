## 원인

1. **실패한 거대 입력의 예약값 미정산.** 두 기록은 앞서 확인한 입력 한도 초과 요청 시각과 일치한다. `ai/global_budget.py`는 요청 JSON 입력의 UTF-8 바이트 수와 최대 출력을 예약하고, 응답에 유효한 `usage.cost`와 `usage.total_tokens`가 함께 있을 때만 실제 값으로 정산한다. 확정적인 요청 거절과 전송 결과가 불명확한 경우를 구분하지 않아 큰 추정값이 남는다. 실제 사용량만으로는 아직 3천만 토큰에 도달하지 않았다.
2. **DAC 범위 확대 조건이 너무 넓다.** `dac_scope_policy.escalation_questions()`는 긍정 근거가 없거나 limitation 근거가 있으면 확대한다. limitation이 존재하는 사실 자체를 실제 사실 충돌과 구별하지 않는다. `expand_documents()`는 해당 질문의 범위를 모든 활성 문서의 전체 본문으로 늘린다. 이번 기록에서 11개 질문 모두 '긍정·반대 근거 동시 존재'로 확대됐다. 사업의 한계도 기록하는 정상 평가에서 이 조건은 전체 재검토를 쉽게 유발한다.
3. **보고서 작성·검토에서 긴 상세 평가 결과 반복 전송.** `_context_for()`는 필요한 기준을 고르지만 `question_assessments` 전체를 포함한다. 현재 5개 기준의 해당 JSON만 합계 699,656자다. 종합 성격의 여러 섹션에서 이를 보내며 초안 생성과 품질 검토에 다시 넣는다. 보고서 36회 요청에 6,249,930토큰, 최대 단일 요청 444,053토큰이 확인됐다. 초안·검토 두 단계 자체와 그때마다 동일한 상세 기록 전체가 필요한지는 구분해야 한다.
4. **재검증 비용 포함.** DAC 최초 실행은 확인 토큰 5,477,384, 첫 복구 1,713,182, 최종 복구 1,815,040이다. 최종 복구에는 42개 근거 선별 요청과 1개 최종 질문 판정이 포함된다. 문서 61개·질문 10개를 재사용했으므로 재시도마다 원문 전체를 처음부터 다시 분석한 것은 아니다.

## 판단과 개선 순서

현재 누적 토큰 전부가 필수 비용은 아니다. 원문 확인, 수치·기간·단위 검증, 상충 근거 검토, 최종 보고서 품질 검토는 필요하다. 그러나 현재의 확대 정책, 긴 상세 평가 기록 재전송, 미확정 예약 처리에는 줄일 여지가 명확하다. 근거를 임의로 잘라 절감률부터 보장해서는 안 된다.

1. 확정 거절·사용량 확인·전송 불명확 상태를 구분해 예약량과 실제 사용량을 별도로 관리한다. 공급자 처리 여부를 확인하지 못한 요청을 임의로 무료 처리하지 않는다.
2. DAC 확대를 질문의 실제 공백·충돌에 필요한 문서와 미검토 구간부터 수행하고 이미 확인한 구간과 등록 사실·출처를 재사용한다. limitation 존재만으로 모든 문서 전체를 다시 읽지 않는다.
3. 보고서 입력을 섹션별 확정 점수·판단·핵심 수치·반대 근거·출처 ID로 구성한다. 상세 원문은 해당 주장 검증에 필요한 범위만 추가한다. 최종 결과의 출처 추적성과 필수 표 행은 유지한다.
4. 비용 보호는 유지하되 모델 가격에 무관한 고정 일일 토큰 수를 주된 차단 기준으로 삼는 정책을 재검토한다. 비용·요청 수·재시도 수·시간 제한과 요청별 입력 한도를 함께 사용하고 차단 전에 예상량을 보여준다.

임시 5천만 토큰 확대는 아직 적용하지 않았다. 이번 조사는 원인과 정책 판단이며 위 최적화는 구현 완료 상태가 아니다.
