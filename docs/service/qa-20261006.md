# 현재 소스 전체 QA 보고서 — 2026-10-06

## 결론

V2.4.23 소스 기준선(`41b3106`)을 새로 빌드하여 백엔드·프런트엔드·브라우저와 실제 HTTP/PostgreSQL 경로를 검증했다. rHWP 편집기 최초 준비 요청의 유실을 재현·수정했고, 수정 후 전체 Playwright 20개가 통과했다. 발견된 문제를 단순 재실행으로 숨기지 않고 로딩을 의도적으로 지연하는 회귀 조건으로 남겼다.

이 보고서는 자동화 및 격리 통합 검증 결과다. 모든 고객 자료의 AI 판단 정확성이나 모든 HWPX의 한컴 출력 품질을 보증하지 않는다. 이번에는 외부 LLM을 호출하여 27개 보고서 섹션을 처음부터 다시 생성하지 않았다.

## 환경과 재현

- QA 이미지: 현재 작업 소스로 `compose.qa.yml` API·웹 빌드 성공.
- 로컬 QA: 독립 `odame-qa` PostgreSQL·파일 볼륨, HTTP 8004. 개발·운영 데이터와 분리.
- 통합 시나리오: 합성 프로젝트 2개, 합성 계획서·PDM·실적 자료. AI 응답은 대체하되 실제 업로드 저장, 작업 실행, HTTP, DB와 RLS를 사용.
- Playwright: Chromium 일반 화면과 800×900 작은 화면, 로컬 정적 서버 및 모의 API. rHWP는 실제 WASM으로 양식을 열고 렌더링·내보내기.
- 실행: `./tools/ops/Test-Service.ps1`, `npm run test:e2e`.
- 추가 통합 도구: `tools/qa_service_refactor.py`, `qa_service_operations.py`, `qa_service_deletion.py`, `qa_service_performance.py`. QA 환경 가드와 전용 볼륨 마운트가 필요하며 운영에서 실행하지 않는다.
- 로그·상세 산출물은 `.runtime/qa-*-20261006.log`, `.runtime/qa-20261006/`, `.runtime/service-tests/`에 로컬 보관. 합성 계정 인증 정보나 브라우저 결과물은 커밋하지 않는다.

## 발견 문제와 수정

### rHWP 동적 로딩 중 준비 요청 유실

- 증상: 저장 단축키 검사에서 `ready timeout`. 동일 브라우저의 다른 실행에서는 통과하여 순서에 따라 달라졌다.
- 원인: iframe의 load 이후에도 동적 Studio 모듈 import가 진행 중일 수 있다. 부모가 보낸 최초 `ready` 요청이 RPC 리스너 등록 전에 도착하면 사라졌다. 실제 선택 섹션 미리보기에서도 같은 순서가 가능했다.
- 수정: `assets/rhwp/studio-loader.js`가 동일 출처 부모의 `ready` 요청만 최대 32개 보존하고, 모듈 로딩 후 원래 RPC로 전달한다. import 실패 시 대기 요청에 오류를 반환한다. 다른 명령이나 다른 출처 요청의 권한을 넓히지 않는다.
- 회귀 검증: Studio JS 응답을 1.2초 지연한 상태에서 최초 ready와 저장 단축키가 완료되는지 양쪽 화면 크기에서 검사한다. 이후 전체 20개 통과.
- 반영 상태: 소스 및 PR에 포함. 이번 QA에서는 운영에 신규 배포하지 않았다.

## 검증 한계와 후속 우선순위

1. **실제 AI 정확도 및 전 구간**: 합성 통합에서는 AI 응답을 대체했다. 신규 사업의 실제 자료로 등록→DAC→27개 섹션 생성→HWPX까지 실행하는 유료 AI 검증은 이번 결과에 포함하지 않는다. 수치·기간·단위·기관 구분의 정확도는 별도 사례 평가가 필요하다.
2. **브라우저 범위**: Chromium 2개 화면 크기다. WebKit/Firefox, 터치 기기, 한컴 데스크톱에서 직접 열기는 미검증이다.
3. **대규모·장시간 운영**: 짧은 읽기 부하는 통과했다. 다수 프로젝트의 대형 PDF 동시 업로드, LLM 공급자 장시간 장애, 수시간 워커 부하 및 메모리 누적을 대변하지 않는다. 실제 프로세스 강제 종료·복원 훈련은 이번에는 재실행하지 않았다.
4. **의존성 경고**: Starlette TestClient의 httpx 전환과 AnyIO BlockingPortal 관련 deprecation 경고 2개가 남았다. 기능 실패는 아니며 의존성 변경 시 호환 검사 필요.
5. **화면 전체성**: 새 DAC 팁의 긴 내용·HTML 이스케이프, 미리보기 선택·복사 등 핵심 회귀는 검증했다. 모든 프로젝트 상태·모든 보고서 페이지에 대한 시각적 승인을 의미하지 않는다.
