# 서비스 리팩토링 작업 기록

## 범위
기존 화면·URL·계정·프로젝트·파일과 평가 결과를 보존한다. 이름 변경과 모듈 분리, 영속 작업 실행,
프롬프트 관리, 운영 가시성, 격리 QA를 함께 수행한다. 운영 전체 데이터 복제는 별도 승인 대기 중이다.

## 순서
1. 현재 테스트 기준선 및 운영 읽기 전용 상태 확인
2. UI 진입점/스타일/스크립트 분리, API 책임별 분리, AI 프롬프트·전송 계층 명확화
3. PostgreSQL 영속 업무 큐와 분석/보고서 워커, 마이그레이션·상태 확인·로그 보강
4. 독립 QA Compose에서 기능/실패복구/계정격리/화면/보고서 검증
5. 결과와 미해결 위험·성능·평가 방법의 한계를 보고서로 정리

## 시작 기준선
- 운영 2개 업무 프로젝트: 문서 62건, 64건. 모두 completed.
- 개발 백엔드: 573 pass, 4 fail, 162 subtests pass. 실패 4건은 이전 구현을 문자열로 고정한 테스트.
- 운영 버전 V2.2.16. 이전 목표값 개선과 등록 사실 추출은 작업공간에 있고 아직 미배포.
- 운영 전체 덤프의 로컬 복제는 자동 승인 검토가 차단. 테스트 자료로 계속 검증한다.

## 완료 기록

- UI/API/AI 프롬프트 분리, 영속 큐, 분석·보고서 워커, 일회성 마이그레이션, 진단 API 반영.
- 백엔드 593개와 하위 검사 162개, 프런트엔드 17개 통과.
- 실제 HTTP/DB 통합 27개, 프로세스 복구 6개, 운영 진단 4개, 프로젝트 삭제 7개 통과.
- 합성 자료를 실제 AI로 분석해 27개 보고서 섹션과 HWPX 55쪽 생성. 최종 목차·내용 보존·조판 검사 통과.
- 최소 분량으로 인한 실패, 등급표 고정 페이지 넘침, 정규화 기본 제목 충돌을 재현·수정.
- 개발 환경 반영, 기존 77개 문서와 프로젝트/매핑/본문 집계 보존 확인. 운영 배포와 고객 데이터 복제는 수행하지 않음.
- 설계·운영·QA 및 남은 과제는 같은 폴더의 `architecture-20260925.md`, `operations-20260925.md`, `qa-refactor-20260925.md` 참고.
