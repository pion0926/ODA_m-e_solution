# 신규 자료·매핑 및 DAC 증분 평가 통합 QA

검증일: 2026-10-08. 환경은 `compose.qa.yml`의 독립 PostgreSQL·파일 볼륨·API/웹(8004)이다. 개발·운영 환경은 이 검사에서 변경하지 않았다. 일반 작업자는 기동하지 않고 HTTP가 접수한 작업을 테스트 프로세스가 직접 실행했다. 모든 자료는 합성이며 외부 AI 요청은 stub으로 대체했다.

## 결과

`tools/qa_service_refactor.py` 실제 HTTP/PostgreSQL 통합 **39개 통과**.

- 사업계획서·PDM 완료 전 일반 업로드 차단, 기준 문서 교체 재확인, 원본·추출문 보존, 문서 등록과 최종 평가 분리.
- 현재 v4 문서 증빙 목적 매핑과 역할 요약·사실 저장, 중복 업로드 방지, 취소·재요청.
- 최초 분석에서 강사 6명·훈련 3회 저장 후 신규 문서가 추가되면 새 문서×지표 1쌍만 분석하여 강사 8명으로 갱신하고 훈련 3회를 유지.
- 동일 문서를 다른 지표에 수동 추가하면 해당 신규 쌍만 분석하여 훈련 4회로 갱신하고 강사 8명을 유지. 완료된 쌍은 다음 제안에서 제외.
- HTTP 중복 요청의 동일 접수 반환, 작업 큐 outbox 원자성, 트랜잭션 실패 롤백, 프로젝트 간 문서·작업 RLS.
- DAC 첫 실행 11개 질문 검증·완료. 한 질문의 문서 선택 변경 후 그 질문만 새로 판정하고 나머지 10개 질문은 검증된 체크포인트를 재사용.
- 근거 부족에 따른 추가 원문 탐색이 질문별 명시적 제외를 무시하지 않음.
- 완료된 현재 DAC 없이 보고서 생성 차단, 주요 조회 API, 별도 로그인 세션의 로그아웃 격리.

`tools/qa_dac_question_reuse.py` 실제 PostgreSQL 롤백 검사 **6개 통과**. 명시 프로젝트 범위, JSONB 체크포인트 출처, RLS, 대기 작업 모델 바인딩, 동일 입력 전체 재사용, 동등한 PDM 재저장 후 11개 질문 재사용을 포함한다.

DAC 범위 탐색·증분·재개·컨텍스트 비용 관련 회귀 **32개 통과**.

2.4.30 후보(API 폴링 응답 축소, DAC 예산 비교범위 검증, 보고서 판정보류·현재성 검증 포함)로 QA API 이미지를 다시 빌드한 뒤 실제 HTTP 통합 **39개** 및 PostgreSQL **8개**를 실행하여 모두 통과했다. DB 검사는 기존 6개에 JSONB 키 순서 정규화와 정확히 일치하는 이전 선별 캐시 재사용 2개를 추가했다. 로그는 `.runtime/qa-cycle-20261008/integration-final30.log`, `checkpoint-rls-final30.log`다.

2.4.31 보고서 고정 공지·개별 기준 점수의 검증 범위 수정 후 전체 백엔드 **1,020개와 하위 검사 183개**가 통과했다. DB 전용 7개는 위 별도 실행으로 검증하며, 프런트 계약 **26개**, Playwright **22개**도 통과했다. 보고서 검증 변화는 실제 실패 초안 2개를 오프라인 대조하여 추가 확인했다.

2.4.34 최종 후보의 전체 백엔드 **1,118개와 하위 검사 189개**가 통과했다. DB 전용 7개는 위 PostgreSQL 격리 실행과 구분하며, 의존성 경고 2건은 실패가 아니다. 프런트 계약 **26개**, Playwright **24개**와 실제 문자를 선택해야 통과하도록 강화한 미리보기 드래그 사례 **2개**도 통과했다. 후속 변경은 백엔드 조판에만 있으며 프런트 동작은 유지된다.

최종 조판 회귀는 글리프의 실제 경계·표 셀 클리핑·푸터 침범, 구역별 인쇄 쪽번호 재시작과 분리된 숫자 글리프, 환류표의 제한된 중복 라벨 투영을 포함한다. 내보내기 재사용은 입력 스냅샷·본문·모델·불변 이미지·렌더러·검증 결과·파일 SHA-256을 모두 대조하며, 하나라도 다르거나 확인되지 않으면 새 파일을 생성한다. 운영 데이터와 파일별 시각 검토 결과는 비공개 로컬 QA 보고서로 따로 보존한다.

2.4.35 후보에서 관측 성과 점수·증빙 신뢰도 분리, 동일 추출 계약의 캐시 호환, 잘못된 보고서 보류 서술 검증 및 혼합 방향 미리보기를 추가했다. 전체 백엔드 **1,170개와 하위 검사 189개**, 프런트 **26개**, Playwright **26개**가 통과했다. DB 전용 7개와 의존성 경고 2건은 앞선 별도 검증 및 의존성 범위로 구분한다. 새 정책은 부분 성과를 보존하고 실제 미관측에는 점수를 만들지 않으며, 과거 평가·하위 질문의 보류를 현재 기준 전체의 보류와 구분한다.

2.4.36 웹 후보는 DAC 최초 진입·새로고침 중 예시 점수가 잠깐 보이던 경로를 제거한다. 응답 지연·최초 조회 실패·후속 갱신 실패를 실제 앱과 합성 API로 검증하여 프런트 **26개**, Playwright **32개**를 통과했다. 저장된 점수는 정상 응답 후 표시하며 후속 실패에도 마지막으로 확인한 점수와 세부 판단을 보존한다. 백엔드와 평가 입력 계약은 변경하지 않았다.

## 발견 및 수정

2.4.38 후보는 성과 결과 저장이 자신의 최신성을 무효화하던 경계를 수정한다. 성과 입력 전용 영수증, 지원되는 과거 측정값의 검증 후 재사용, 접수 후 매핑 변경 차단, 실행 시점 모델 변경에 대한 승인 범위 내 재검토를 포함한다. 전체 백엔드 **1,214개 및 하위 검사 189개**, 프런트 **26개**, Playwright **32개**가 통과했다. 집중 회귀는 **135개 및 하위 검사 4개**다. DB 전용 7개와 의존성 경고 2건은 기존 격리 검사 및 의존성 범위로 구분한다. 정상 운영 이행과 새 산출물 검증 기록은 로컬 QA 문서에 보관한다.

같은 2.4.38 소스로 격리 QA API·웹을 다시 빌드한 뒤 **실제 HTTP 39개·PostgreSQL 8개**도 통과했다. 기존 fixture를 변경하지 않았고 원문 공급자 호출은 stub으로 처리했다. 신규 문서와 수동 연결의 증분 실행, 질문별 재사용, 같은 입력의 전체 재사용, RLS·JSONB·대기 모델 바인딩을 실제 DB와 HTTP 경로로 재검증했다.

2.4.39 웹 후보는 보고서 화면 진입 시 캐시된 이전 완료 기록이 진행 중 작업 트레이를 덮는 문제를 수정한다. 새 서버 응답만 트레이를 갱신하며 화면 진입 시 최신 생성 상태를 조회한다. 수정 전 코드에서 결함을 재현한 회귀를 포함해 프런트 **27개**, Playwright **32개**가 통과했다. 개발 HTTP 응답이 테스트한 소스와 일치함을 확인했다. API·분석 정책·본문·DB는 2.4.38을 유지한다.

2.4.37 출력 후보는 고정 공지의 기관명 치환으로 생긴 중복과 정량 비교 한계의 오해 소지를 수정한다. 성과표의 알려진 내부 선택 라벨도 독자용 문구로 투영한다. 최종 전체 백엔드 **1,193개 및 하위 검사 189개**가 통과했다. DB 전용 7개는 별도 격리 검사와 구분하며 의존성 경고 2건이 있다. 출력 관련 회귀 **51개**가 통과했고 프런트는 2.4.36의 **26개 / Playwright 32개** 이후 변경하지 않았다. 저장된 평가·본문과 분석 프롬프트를 변경하지 않으며 운영 산출물의 최종 검증은 로컬 QA 기록에 남긴다.

1. 이전 통합 fixture의 v3 자동 매핑이 현재 v4 목적 구분 계약과 달랐다. 현재 매핑 버전과 `reported_result` 의미를 사용하도록 수정했다.
2. 원문 탐색이 무관한 모든 축의 인용에 가중치를 주던 부분을 질문별 사실·현재 DAC 기준으로 좁혔다.
3. 새 선택에는 자동 제안과 사용자 추가·제외 이력을 구분해 저장한다. 과거 구분 없는 선택은 호환 보존한다.
4. 실제 통합 실행에서 추가 원문 탐색이 사용자 제외 문서를 복원하는 문제를 발견하여 수정하고 재검증했다. 상세는 `issues/dac-focused-navigation-20261008.md`에 기록했다.

## 범위와 재현

AI 추론의 정확도, 실제 문서 품질, 운영 보고서/HWPX의 시각적 품질은 이 합성 검사의 통과가 보증하지 않는다. 운영 데이터 평가와 보고서·실제 화면 검토는 별도 검증이다. 최종 DAC 합성 결과는 점수를 꾸며 채우지 않고 근거 부족 판정보류로 저장했다.

실행은 QA API/웹 기동 후 `KODAME_QA=1`, 빈 `OPENROUTER_API_KEY`, QA 전용 `DATABASE_URL`로 두 도구를 실행한다. `qa_service_refactor.py`는 `/qa` 쓰기 경로와 QA 파일 볼륨이 필요하다. 실제 자격증명·생성물은 커밋하지 않으며 로컬 로그·JSON 결과는 `.runtime/qa-cycle-20261008/`에 보관한다.
