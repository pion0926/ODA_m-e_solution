# 리팩토링 QA 및 서비스 개선 검토

작성일: 2026-09-25. 기능별 코드 분리, 영속 작업 실행, 분리 워커, AI 호출 관리와 격리 QA를 검증했다.
기술적 실행 안정성 검증과 평가 내용의 타당성 검증은 구분한다. 이 결과를 모든 운영 자료에 대한 정확도 보장으로 해석하면 안 된다.

> 이 문서는 1차 리팩토링 당시 기록이다. 아래 우선 개선 18개 항목의 후속 구현·최신 QA·V2.4.0 개발/운영 배포 결과는
> [개선 완료 기준 검증 기록](improvements-20260925.md)을 따른다. 아래의 운영 미배포·관리자 비밀 미분리·직렬 워커 등의 설명은 당시 상태다.

## 환경과 데이터

- 운영의 두 업무 프로젝트를 **읽기 전용 집계**로 확인했다. knut는 활성 문서 62건·작성 섹션 27개, 다른 프로젝트는 문서 64건이었다. 모두 문서 등록 완료 상태였고 진행 중 작업은 없었다.
- 운영 모델은 각각 `openai/gpt-5.6-luna`, `google/gemini-3.5-flash-lite`였다. 모델이나 원문·평가·계정을 변경하지 않았다.
- 운영 전체 DB/파일을 로컬로 복제하는 작업은 자동 승인 검토가 고객·계정 데이터의 대량 로컬 복제에 대한 구체적 승인이 없다는 이유로 차단했다. 승인 질문에 응답이 없어 실행하지 않았다.
- QA는 `odame-qa`의 독립 DB/파일 볼륨과 가상 계정을 사용했다. 합성 사업계획·PDM·실적 자료이며 고객 자료를 복사하지 않았다.
- 개발 서버는 기존 두 프로젝트의 문서 77건을 유지하면서 검증한 이미지와 새 Compose 구성을 반영했다. 운영 서버는 이번 변경을 배포하지 않았다.

자동 QA는 출력 형태까지 검증하지만, 모든 고객 PDF/HWP의 실제 렌더링과 사실 판단을 사람처럼 평가한 것은 아니다.
Starlette TestClient/AnyIO 관련 deprecation 경고 1건이 남아 있다. 실패는 아니지만 의존성 정비 대상이다.
브라우저에서는 재배포 중 일시적 네트워크 오류와 출처 URL 없는 MutationObserver 오류를 관찰했다.
화면 기능은 이후 정상 동작했다. 출처 없는 오류를 서비스 코드 문제로 확정하거나 콘솔 무오류로 보고하지 않는다.

## 이번 QA에서 발견해 수정한 문제

1. **PDM 최소 1,500자**: 지표가 적으면 원문을 충실히 옮겨도 실패했다. PDM 분량 강제를 제거했다.
2. **평가매트릭스 1,706/1,800자 실패**: 목표 분량을 유효성 검사로 사용했다. 분량은 품질 경고로 남기며 본문 저장을 막지 않게 했다. 구조·금지 사실·수치 검사는 유지한다.
3. **등급표 높이 67,070/58,000 초과**: 질문 이유가 길 때 고정 2쪽 그룹이 넘쳤다. 기준별 병합 셀과 모든 문장을 유지하면서 높이에 맞춰 페이지 그룹을 구성한다.
4. **평가 목적 서식 자기 충돌**: 정규화기의 기본 제목이 중복 금지 제목과 같아 사전 검사에서 거부됐다. 기본 제목을 구분하고 반복 적용해도 동일하게 유지되는 회귀 검사를 추가했다.
5. **API 재시작과 장시간 작업 결합**: 작업을 영속 큐와 전용 워커로 옮겼다. 접수/큐 원자성·중단 상태·부분 성공·취소를 검사했다.
6. **추적 정보 부족**: HTTP 요청 ID, 관리자 큐 집계, 접수/실행 프롬프트 지문을 추가했다.

통합 도구 자체의 예상 HTTP 코드·정렬 열·모듈 경로 오류도 실행 과정에서 수정하고 최종 검사를 다시 수행했다.
합성 자료 생성 단계에서 사업개요를 생략한 경우 HWPX가 사업명 누락을 거부했다. 실제 계획서 분석/사업개요 경로를 실행한 뒤 검증했다.

## 성능 관찰

로컬 합성 4문서 프로젝트에서 읽기 API 80건을 동시성 8로 요청한 결과 오류 0건,
중앙값 72.8ms, p95 117.5ms, 최대 159.9ms였다. 대시보드·PDM·등록 목록·건강 확인을 포함한다.
이는 대형 PDF 파싱, 운영 126문서 재분석, 수십 프로젝트 동시 사용, 장시간 부하를 측정한 수치가 아니다.

전체 보고서 생성은 짧은 합성 입력에서도 약 407초가 걸렸고, 실패 섹션 이어쓰기는 약 10초였다.
섹션별 생성/검토·복구 호출이 누적되기 때문이다. HWPX 검증 성공 시점은 약 10초였다.
모델·제공자·캐시·문서 길이에 따라 변하며 서비스 SLA로 쓰면 안 된다.

## 아직 수행하지 않은 검증

운영 고객 자료 전체 재분석·두 계정 보고서 재생성, 운영 백업 복원, 한글 데스크톱 앱 인쇄,
모든 15/30쪽 발표자료의 실제 AI 생성, 모든 번역 언어의 사람 검수, 장시간 대용량 부하, 외부 보안 감사는 수행하지 않았다.
해당 기능의 기존 자동 회귀 검사와 실제 고객 데이터로 완주하는 검사는 동일하지 않다.
