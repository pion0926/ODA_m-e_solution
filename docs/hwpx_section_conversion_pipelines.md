## 공통 변환 순서

1. DB에서 저장된 전문가 초안 원문을 읽는다. 내보내기 과정에서 일반 문구로 재생성하거나 덮어쓰지 않는다.
2. Unicode NFKC 정규화 후 제어문자, zero-width 문자, 이스케이프된 HWPX 제어태그, 내부 근거 ID, 내부 섹션 slug를 제거한다.
3. Markdown 제목은 원본 양식에 이미 있는 장·절 제목이면 제거하고, 실제 하위 제목은 `가.`, `나.` 형식의 보고서 소제목으로 바꾼다.
4. Markdown 표는 구조화 섹션이면 셀 데이터로 파싱하고, 일반 본문이면 행별 제목·값 문단으로 바꾼다. `|---|` 같은 작성 표시는 남기지 않는다.
5. 본문은 육안 폭에 맞춘 강제 줄바꿈을 하지 않는다. 의미 문단·소제목·항목 하나마다 원본 입력 문단을 복제하고 원본의 `styleIDRef`, `paraPrIDRef`, `charPrIDRef`를 상속한다.
6. 내용이 바뀐 물리 구역은 기존 좌표 캐시와 신규 문단이 섞이지 않도록 그 구역의 `linesegarray`를 모두 제거한다. Hancom/rhwp/kordoc이 원본 문단·글자 스타일을 기준으로 구역 전체를 일관되게 재조판한다. 변경하지 않은 ZIP 엔트리는 보존한다.
7. 표는 검토된 값 셀만 바꾼다. 열 너비, 행·열 병합, 테두리, 음영, 캡션, 셀 여백은 원본을 그대로 보존한다.
8. 원본 ZIP 엔트리를 순서·압축 메타데이터와 함께 보존하고 수정 대상 `section*.xml`만 교체한다.
9. 로컬 검사에서 내부 ID, 다른 사업 샘플 문구, HWPX 태그 노출, Markdown 잔재를 차단한다.
10. kordoc으로 ZIP/XML 유효성, 파싱 블록, 표 프로파일, 편집 capability, 재조판 페이지 수와 렌더 경고를 검사한다. rhwp 화면 미리보기는 최종 육안 검토에 사용한다.

## 어댑터 v2 구조

양식 주소, 내용 합성, 표기 정규화, XML 치환, 적용 검증을 한 함수에 섞지 않는다. 각 논리 섹션은 아래 5단계를 순서대로 통과하며, 앞 단계가 실패하면 다음 단계와 HWPX 쓰기를 실행하지 않는다.

1. **슬롯 계약**: 논리 섹션 ID, structured schema, 물리 XML 경로, 슬롯 키, 문단·셀 주소, 문단 계층, 글자·문단 스타일, 허용 길이를 코드로 고정한다.
2. **의미 합성**: 관련 섹션과 현재 프로젝트 필드만 사용해 각 슬롯의 본문을 합성하고, 슬롯별 출처와 결정론적 보완 여부를 기록한다.
3. **형식 정규화**: `가.` → `ㅇ` → `-` 계층, 중복 하위 라벨, 페이지 인용, Markdown, 한 문단 제한을 슬롯별 규칙으로 정규화한다.
4. **XML 적용**: 검토된 manifest를 주소표로만 사용해 기존 문단·셀의 값만 바꾼다. manifest의 주소가 코드 계약과 다르면 즉시 실패한다.
5. **완전성 검증**: 최종 XML에서 모든 슬롯의 실제 텍스트, `paraPrIDRef`, `charPrIDRef`를 다시 읽어 코드 계약과 정확히 비교한다.

국문 요약(논리 섹션 5)은 이 구조를 우선 적용한 `summary_27_slots_v2` 어댑터다. 27개 슬롯 전체가 유효한 structured JSON으로 준비되어야 하며, 일부 슬롯만 받은 뒤 과거 예시문이나 `추가 정보 필요`를 합치는 레거시 fallback은 허용하지 않는다. 어댑터 레지스트리는 후속 섹션을 같은 구조로 옮길 수 있게 합성기 ID와 실행 함수를 분리한다.

## 고정 양식 특수 조판 규칙

- 표지의 공식 사업명은 별도 `project_title` 슬롯, 보고서 유형은 다음 고정 문단에 별도 슬롯으로 쓴다. 사업명이 19자 이상이면 원본 표지 전용 글자속성 58의 48pt를 42pt, 36pt, 32pt 중 길이에 맞게 축소한다. 글꼴·굵기·정렬은 바꾸지 않는다. 긴 진행상태 문구는 표지에서 `현시점 평가보고서`로 압축하되 다운로드 파일명에는 전체 보고서 유형을 유지한다.
- 평가등급표 질문별 산정이유는 완결된 핵심 판단 1문장, 최대 62자로 제한한다. 종합행은 65자 이내로 유지해 고정 행 높이에서 글자가 겹치지 않게 한다.
- 평가매트릭스는 원본에서 소제목과 같은 문단 안에 인라인 표로 배치되어 있으므로, 내보낼 때 표 런을 `paraPrIDRef=15`, `styleIDRef=0`인 독립 문단으로 이동한다. 표 자체의 너비·열·셀 속성은 그대로 유지한다.
- 마지막 교훈 표는 원본의 마지막 페이지 밖에 매달리지 않도록 `(2) 교훈` 제목에 강제 쪽 나눔을 적용한다. 교훈 표는 새 가로 페이지에서 시작한다.
- 성공 판정은 HWPX 필수 엔트리와 9개 물리 구역, 조판 캐시 0개, kordoc 20~100쪽, 표 9개 이상, 이미지 3개 이상을 모두 만족해야 한다. 현재 실제 결과는 kordoc 33쪽·표 11개·이미지 3개, rhwp 28쪽이다.

## 실패 방지 규칙

- 현재 사업이 진행 중이면 문서명과 공지에 `현재시점 문헌기반 평가보고서`를 사용하고 완료 사실을 단정하지 않는다.
- 지원기관·수행기관은 사업개요의 현재 값을 사용한다. 고정 양식의 과거 KOICA 예문과 네팔·무구 샘플 문구는 독자 텍스트에 남기지 않는다.
- 셀 텍스트가 지나치게 길면 문장 경계에서 압축하되 표 구조를 늘리거나 열 너비를 임의로 바꾸지 않는다.
- 실제 조사 증빙이 없는 면담·현지조사·신규 설문은 수행한 것으로 바꾸지 않는다.
- 변환 단계는 결정론적으로 동작한다. 내용 작성과 논증은 LLM 단계에서 수행하고, HWPX 조판 단계에서는 사실을 추가하거나 문장을 새로 평가하지 않는다.
