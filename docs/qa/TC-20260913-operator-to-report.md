# 운영자 발급 → 사용자 자료 등록 → PDM → DAC → 보고서 시나리오 TC

## 실행 원칙

- 기존 계정·프로젝트·저장 보고서를 덮어쓰지 않음. 신규 테스트 프로젝트와 연결 계정으로 실행함.
- 각 단계의 통과 조건을 먼저 검증함. 결함 발견 → 수정 → 동일 단계 재시험 후에만 다음 단계로 진행함.
- 브라우저 조작과 실제 화면 확인을 기본으로 하고, 자동 회귀·API/RLS 검증을 보조 증거로 사용함.
- 실제 AI 시험은 기존 OpenRouter 경로를 사용하며 요청 및 결과를 프로젝트별로 분리함.
- 이번 데이터는 사용자가 제공한 KNUT 자료의 로컬 원본 중 최신 PDM·실적표·사업계획·자체평가·교육/기자재 증빙을 사용함. 샘플 보고서 내용이나 다른 계정의 평가 결과는 복사하지 않음.
- 미확인·잠정 판단과 실패를 구분함. 근거가 없는 성과를 성공으로 만들지 않음.

## 1. 운영자 프로젝트·계정 발급 게이트

| ID | 검증 | 통과 조건 |
|---|---|---|
| A01 | 관리자 로그인 | 프로젝트 관리로 진입, 좌측에 프로젝트·사용자 관리만 표시 |
| A02 | 사용자 화면 직접 주소 접근 | 관리자 작업 영역으로 복귀, 사업 API 403 |
| A03 | 프로젝트 생성·언어 선택·취소 | 취소 무변경, 필수값 검증, 완료 시 자료/평가/작성 본문 0 |
| A04 | 프로젝트 연결 계정 발급 | 선택 프로젝트와 계정 원자적 저장, 기본 작업 권한 명시, 임의 다른 프로젝트 접근 없음 |
| A05 | 중복·잘못된 아이디 | 오류 안내, 계정 중복 및 잘못된 배정 없음 |
| A06 | 계정 발급 응답 | 비밀번호 자동 난수·일회 표시·no-store·목록/API 재노출 없음 |
| A07 | 프로젝트 검색·사용자 필터·상세 | 선택한 프로젝트/계정의 정확한 정보 및 상태 표시 |
| A08 | 메뉴 권한 저장 | UI와 서버 생성 권한 일치, 권한 거부 시 403 |
| A09 | 계정 중지/재활성·프로젝트 배정 변경 | 중지 즉시 세션 종료, 자료 보존, 소속 외 프로젝트 차단 |

## 2. 사용자 로그인·문서 등록 게이트

| ID | 검증 | 통과 조건 |
|---|---|---|
| U01 | 발급 계정 로그인 | 연결 프로젝트 대시보드, 문서/성과/평가 0, 관리자 메뉴 없음 |
| U02 | 빈 화면 안내·메뉴 이동 | 샘플 사실 없음, 문서 등록 다음 행동 안내 |
| U03 | PDF/XLSX 등 원본 다중 업로드 | 각 파일 목록/처리 상태/오류 사유 표시, 새 프로젝트에만 저장 |
| U04 | 처리 완료·중복 파일 재등록 | 중복 관리 정상, 원본 중복으로 성과가 증가하지 않음 |
| U05 | 문서 검색·필터·다운로드·증빙 분류 | 원본과 연결 일치, PDM/DAC 자동 배정, 원문 접근 가능 |
| U06 | 프로젝트 격리 | 다른 프로젝트 선택·문서 다운로드·보고서 접근 불가 |

## 3. PDM 평가 게이트

| ID | 검증 | 통과 조건 |
|---|---|---|
| P01 | 사업개요·최신 PDM | 최신 1개가 기준, Impact/Outcome/Output/Activity/Input 구조 일관 |
| P02 | 지표 갱신 | 최신 등록 자료 사용, 중복 실행 방지, 상태 안내 및 완료 |
| P03 | 성과지표 모니터링 | OVI만 표시, 성과 구분·목표/실적/달성도·근거 연결 정확 |
| P04 | 대시보드·그래프 | 지표 데이터 일치, 90% 초록/70% 노랑/미만 빨강, 미확인은 0% 아님 |
| P05 | 증빙 펼치기·리스크 확대 | 세부 문서·권고 읽기 가능, 위험은 지표별 자료에 기반 |

## 4. DAC 평가 게이트

| ID | 검증 | 통과 조건 |
|---|---|---|
| D01 | 평가 실행 | 최신 PDM 및 완료 문서 사용, 실행 중 중복 방지 |
| D02 | 11개 질문·33개 내부 확인 항목 | 항목별 충족/일부/미충족/미확인과 실제 근거 설명 모두 존재 |
| D03 | 1~4점 기준 및 적용 | 선택 점수 이유·상위 점수 경계·버전 표시, 4점은 모든 항목 충족 |
| D04 | 불확실성 | 자료 부재를 실패로 단정하지 않음, 미확인 포함 시 잠정 표시 |
| D05 | 기존 평가 호환 | 새 적용 내역을 꾸며내지 않으며 재평가 안내 |
| D06 | 분석 결과 UI | 원문 보기 제거, 증빙 기본 접힘, 점수표는 내부 기준임을 명시 |
| D07 | 대시보드와 진단 | 5개 기준 합계/20·질문별 평균 정확히 일치, 영향 추가 금지 |

| ID | 검증 | 통과 조건 |
|---|---|---|

| R02 | 선택 섹션 AI 수정·미리보기 | 해당 섹션 저장/실제 rHWP 반영, 다른 섹션 불변 |

| R04 | rHWP 검토 | 표지/목차/등급/사업개요/PDM/평가매트릭스/성과달성도/변화이론/결론 확인 |
| R05 | 문서 품질 | 목차 페이지 우측 정렬·실제 쪽수 대응, 표 글자 겹침/잘림·불필요 공백 없음 |
| R06 | 제목·문단 규칙 | 종료평가 결과보고서 제목, 번호/ㅇ/- 계층·제목 전 여백·중복 괄호 최소화 |
| R07 | 추가 자료 후 재평가·재생성 | 최신화 필요 표시, 이전 초안 보존, 재평가 후 생성 허용 |

## 기준 관리 위치

- 질문/1~4점: `redesign/backend/kodame_intake/evaluation_criteria.py`
- 질문별 구체 확인 항목: `config/dac_scoring_checks.json`
- 적용 내역 검증: `redesign/backend/kodame_intake/dac_scoring.py`
- 생성 프롬프트/재시도: `redesign/backend/kodame_intake/evaluation_runner.py`
- 분석 결과 표시: `assets/dac-scoring-ui.js`
- 운영자 계정 발급: `assets/service-admin-ui.js`, `admin.py`, `service_admin_api.py`

평가 관점은 [OECD의 적용 지침](https://www.oecd.org/en/publications/applying-evaluation-criteria-thoughtfully_543e84ed-en.html)을 참고하되, 1~4점과 서비스의 5개 기준 구성은 프로젝트 내부 운영 기준임. 실제 점수는 근거에 대조한 AI 보조 판단이며 평가자의 검토가 필요함.
