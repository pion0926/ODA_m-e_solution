# K-ODAME 보고서 27개 섹션별 QA 체크리스트

## 사용 방법

1. 보고서 자동작성 완료 후 편집 화면에서 1번부터 27번까지 각 섹션의 내용과 근거를 먼저 평가한다.
2. 27개 섹션이 모두 통과하면 `HWPX 저장`을 실행한다.
3. 저장된 최신 파일을 `rhwp 미리보기`로 열어 같은 27개 행의 양식·문자·시각 항목을 완성한다.
4. 한 항목이라도 FAIL이면 해당 섹션 종합 결과는 FAIL이다. 미평가 항목이 있으면 전체 보고서를 PASS 처리하지 않는다.

## 공통 판정 기준

| 평가축 | PASS 기준 |
|---|---|
| 내용 | 섹션 목적·필수내용·분량에 적합하고 다른 섹션의 내용을 무의미하게 반복하지 않음 |
| 근거 | 현재 프로젝트의 허용 근거만 사용하며 사업정보·PDM·지표·DAC 수치와 일치하고 추적 가능 |
| 구조 | 섹션별 제목·소제목·문단·목록·표 순서와 adapter 입력 구조가 원본 양식과 일치 |
| 양식 | 들여쓰기 깊이, 번호/글머리 기호, 정렬, 줄간격, 표 셀 위치·병합·숫자 정렬이 원본 템플릿과 일치 |
| 출처 표현 | 본문에 업로드 파일명·확장자·경로·UUID를 노출하지 않고 사람이 읽는 문서명/기관명·연도·필요한 쪽수로 표현 |
| 문자 | 원시 Markdown, placeholder, 내부 UUID, 대체문자, 깨진 글리프가 없음 |
| rhwp 시각 | 최신 HWPX가 표시되고 잘림·겹침·고아 제목·비정상 빈 페이지·표 이탈이 없음 |
| few-shot 격리 | 해당 섹션 프롬프트가 우수 샘플의 형식·구성만 예시로 사용하고 샘플 사업의 사실·문장·수치·기관을 생성 내용에 사용하지 않음 |
| 생성-적용 대응 | 해당 part_id에 전용 텍스트 생성 계약과 전용 HWPX adapter/manifest가 각각 1개씩 존재하고 생성값이 지정 문단·셀에만 적용됨 |
| 편집-HWPX 일치 | 편집 화면의 최신 저장 문장이 adapter 입력과 HWPX 추출 텍스트에서 의미상 동일하며 날짜·괄호·긴 문장 중간이 잘리지 않음 |

## 사용자 우려사항 강화 판정

아래 항목은 해당 섹션의 종합 PASS에 필수다. `확인 대상`이 하나라도 FAIL이면 27개 섹션 결과표의 해당 행도 FAIL로 기록한다.

|---|---|---|---:|---|
| RPT-ARCH-001 | 전체 27개 | 27개 part_id마다 전용 텍스트 생성 계약 1개와 HWPX 적용 계약 1개가 있어 27+27=54 대응이 성립 |  |  |
| RPT-PROMPT-001 | 전체 27개 | 모든 프롬프트에 few-shot 예시와 형식만 참고·내용 사용 금지·현재 프로젝트 근거만 사용 규칙 존재 |  |  |
| RPT-PROMPT-002 | 전체 27개 | 샘플 고유 사업명·국가·기관·수치·문장이 편집 본문과 HWPX에 0건 |  |  |
