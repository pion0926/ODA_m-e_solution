# 대시보드·사업개요 다국어 설계

## 적용 범위

- 지원 언어: 한국어, 영어, 베트남어, 러시아어, 우즈베크어
- 대시보드: 메뉴·버튼·상태 문구, 사업명, 성과지표, PDM 리스크·개선권고, DAC 기준·질문·판단 근거
- 사업개요: 기본정보, 사업목적·수혜자·활동·산출물·성과, PDM 준비도, PDM 표의 성과 구조·지표·검증수단·가정·위험
- 원본 식별값: 문서 파일명, UUID, 상태 코드, 지표 코드, 점수, 날짜, URL은 번역하지 않음

## 처리 흐름

```text
언어 선택
  -> 정적 UI 사전 적용 준비
  -> 대시보드·사업개요·PDM·DAC 표시 데이터 수집
  -> 사람이 읽는 필드만 추출
  -> 대상 언어로 전체 번역
  -> 키 누락·빈 문장 완전성 검증
  -> 프로젝트 + 언어 + 원문 해시 단위 캐시
  -> 정적 UI와 동적 데이터를 한 번에 화면 반영
```

번역이 끝나기 전에는 기존 언어 화면을 유지한다. 번역 일부만 성공했거나 응답 형식이 잘못된 경우 언어 변경을 취소하므로 한 화면에 한국어와 대상 언어가 섞이지 않는다.

## 코드 경계

- `translations.py`: 버튼, 제목, 상태처럼 개발자가 직접 관리하는 고정 UI 사전
- `localized_views.py`: 프로젝트별 동적 문장 추출, 번역, 검증, 병렬 배치, 캐시
- `project_i18n.py`: 사업에서 허용한 언어와 사용자의 선택 언어 결정
- `main.py`: 대시보드·사업개요 통합 번역 API
- `odaon-v1-live.js`: 언어 변경 트랜잭션, 캐시 재사용, 렌더링 갱신

고정 UI 문구를 수정할 때는 `translations.py`의 5개 언어 값을 함께 수정한다. 동적 데이터의 새 표시 필드는 `localized_views.py`의 `TRANSLATABLE_KEYS`에 명시적으로 추가한다.

## 캐시와 갱신

번역 결과는 `project_content_translations`에 저장한다. 번역 대상 원문과 필드 경로를 SHA-256으로 계산하므로 사업개요, PDM, 성과 리스크 또는 DAC 결과가 바뀌면 이전 캐시를 사용하지 않고 새 번역을 만든다. 동일 내용과 언어의 재방문·새로고침은 저장된 번역을 즉시 사용한다.

## 안전 원칙

- PDM, DAC, OECD, KOICA, OVI와 사업 고유 약어는 유지함
- 숫자, 단위, 날짜 범위, 점수와 배열 순서를 변경하지 않음
- 요약하거나 새로운 사실을 추가하지 않음
- UUID·상태 코드·링크 등 애플리케이션 계약값은 모델 입력에서 제외함
- 모든 문장이 번역된 경우에만 캐시하고 화면에 적용함
