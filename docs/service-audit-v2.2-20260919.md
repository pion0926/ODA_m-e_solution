# 서비스 점검 및 v2.2 개발 서버 반영

2026-09-19 · 개발 서버 http://127.0.0.1:8002 · API 버전 2.2

관리자부터 사용자 화면까지 점검하고 아래 세 영역을 개선했다. 개발 API·작업자·웹을 교체했으며, 운영 서버는 변경하지 않았다.

## 1. 관리자 계정·프로젝트 배정

- 여러 프로젝트를 배정하거나 해제할 때 한 번의 요청·DB 트랜잭션으로 저장한다. 잘못된 프로젝트가 하나라도 있으면 전체 변경을 취소한다.
- 같은 계정을 두 관리자가 동시에 수정하면 먼저 저장한 변경만 반영하고, 나중 요청에는 최신 목록을 확인하도록 안내한다.
- 배정 해제 시 해당 프로젝트 선택 세션을 무효화한다. 계정 이용 중지 상태에서도 배정 해제는 가능하며, 새 배정은 활성화 후 허용한다.
- 계정 발급 직후 일회용 비밀번호를 먼저 표시한다. 이후 목록 새로고침이 실패해도 발급된 비밀번호 화면을 잃지 않는다.
- 상세 카드에는 참여 프로젝트 전체를 표시한다. 긴 한·영 프로젝트명과 모바일에서 카드가 좁아지던 문제를 수정했다.

## 2. 자료 업로드·분석 오류 복구

- 업로드 결과를 `새로 접수 / 기존 동일 파일 / 미접수`로 나누어 화면에 유지한다.
- 지원하지 않는 형식, 빈 파일, 크기 초과는 해당 파일만 거절하며 뒤의 정상 파일은 계속 접수한다. 서버의 다중 파일 API도 파일별 결과를 반환한다.
- 미접수 파일의 이름과 이유, 해당 파일만 다시 업로드하는 버튼을 제공한다. 동일 파일은 중복 적재하지 않는다.
- 문서 목록에 분석 실패·AI 연결 대기 원인과 `분석 재시도` 버튼을 표시한다. 이미 재시도 큐에 들어간 문서는 중복 접수하지 않는다.
- 실패 문서가 있을 때 계속 기다리라고 표시하던 평가·보고서 안내를 원인 확인 및 재시도 안내로 변경했다.
- 200건을 넘는 프로젝트도 페이지 커서를 따라 전체 문서를 조회한다. 조회 중 새 파일이 추가되어도 기존 페이지가 중복되지 않는다.
- 모바일에서는 파일 목록을 카드 형태로 표시해 실패 원인과 재시도 버튼이 잘리지 않게 했다.

## 3. 계정·프로젝트 전환 시 작업 보호

- 웹 요청에 화면을 처음 연 계정·프로젝트 식별자를 포함하고 서버에서 현재 세션과 대조한다.
- 다른 탭에서 프로젝트 또는 계정을 바꾼 뒤 이전 화면으로 업로드·평가·보고서 생성 등을 실행하면 409 응답으로 차단한다. 기존 API 호환성을 위해 식별자가 없는 외부 클라이언트는 종전의 세션 범위를 사용한다.
- 계정 이용 중지·로그인 만료도 안내창으로 처리한다. 화면을 강제로 새로고침하지 않고, 아직 실행하지 않은 보고서 수정 요청을 복사할 수 있게 보관한다.
- 안내 후 진행 중이던 화면 요청의 응답도 버려 다른 프로젝트 데이터가 섞이지 않도록 한다. 사용자가 작업 공간을 다시 열면 기존 화면의 문서·평가 상태를 초기화한다.
- 언어 변경도 동일한 요청 검증을 거친다.

새 유료 LLM 평가나 전체 보고서·PPT 생성은 이번 점검에서 실행하지 않았다. 보고서·PPT는 기존 회귀 테스트와 화면·API·선행조건을 검증했으며, user01의 작성된 보고서 섹션은 현재 0개다. 따라서 이번 점검을 새 완성 보고서·PPT 파일의 실물 검수로 해석하면 안 된다. 기존 실제 DAC 결과는 그대로 조회했다.

파괴적인 시나리오는 별도 DB에서 실행했다. 실제 user01 화면 점검에는 QA 전용 세션을 만들고 종료 시 폐기했으며, QA 로그인 기록 외 사업 데이터는 변경하지 않았다. 운영·개발 계정 비밀번호는 재설정하지 않았다.
