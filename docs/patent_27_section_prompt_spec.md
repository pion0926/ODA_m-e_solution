# 종료평가 결과보고서 27개 섹션별 AI 프롬프트 설계 명세서

본 문서는 ODA M&E 솔루션의 `5-1 종료평가 결과보고서` 자동 작성 기능에서 사용하는 27개 섹션별 AI 프롬프트를 특허 출원 검토용으로 정리한 자료다. 목적은 단순한 프롬프트 목록을 제시하는 것이 아니라, 각 섹션 프롬프트가 어떤 입력자료를 참조하고, 어떤 생성 기준으로, 어떤 형식의 결과물을 산출하는지를 기술 구성 관점에서 설명하는 데 있다.

원본 기준 파일은 `prompts/Section1_*.py`부터 `prompts/Section27_*.py`이며, 애플리케이션은 `backend/report_prompts.py`에서 해당 프롬프트를 로드해 보고서 에디터의 27개 작성 파트에 연결한다.

## 1. 시스템 목적

본 시스템의 프롬프트 설계 목적은 평가보고서 전체를 한 번에 생성하는 방식이 아니라, 종료평가 결과보고서 양식의 27개 작성 단위를 독립 프롬프트로 분해하고, 각 섹션별 입력자료, 근거자료, 선행 분석 결과, 출력 형식을 다르게 통제하여 HWPX 원본 양식에 바로 반영 가능한 보고서 본문 또는 슬롯 값을 생성하는 것이다.

특허 출원 관점에서 핵심 목적은 다음과 같다.

- 평가보고서 양식의 각 섹션을 고정된 작성 단위로 식별하고, 섹션별 전용 프롬프트를 적용한다.
- 프로젝트 기본정보, 기준별 평가결과, 업로드 증빙, RAG 참조문서, 기존 작성본, 사용자 수정요청을 섹션별로 다르게 결합한다.
- 표지, 목차, 공지, 평가등급표, 사업개요표, PDM 등 구조화 영역은 JSON 슬롯으로 생성하고, 기준별 평가결과와 결론부는 최종 보고서 본문 텍스트로 생성한다.
- 근거가 없는 사실을 생성하지 않도록 제한하면서, 자료가 제한적인 경우에는 확인 가능한 자료 범위와 판단 한계를 자연스러운 보고서 문장으로 반영한다.
- HWPX 원본 양식의 제목, 표, 문단 수, XML 구조를 보존한 채 생성 결과만 치환할 수 있도록 출력 계약을 섹션별로 고정한다.

## 2. 공통 입력 및 처리 구조

27개 프롬프트는 섹션별로 참조 범위가 다르지만, 공통적으로 다음 입력 체계를 사용한다.

- `previous_text`: 현재 섹션의 기존 문구, 이전 JSON 슬롯 값 또는 사용자가 수정한 현재 작성본.
- `content_inputs.project`: 사업명, 기간, 예산, 대상국, 대상지역, 사업개요 문서명 등 프로젝트 기본정보.
- `content_inputs.criteria`: DAC 기준별 평가질문, 점수, 핵심 판단, 증빙 공백, 평가결과 요약.
- `content_inputs.overall`: 종합점수, KOICA 평가등급, 국무조정실 평가등급 등 총괄 평가정보.
- `grade_score_rows`: 시스템이 산정한 평가등급표용 기준별·질문별 점수 행.
- `reference_corpus`: 업로드 문서와 참조문서에서 섹션 관련성이 높은 문단을 선별한 근거 자료.
- `prior_analysis_sections`: 앞서 생성된 사업개요, 평가개요, 성과달성도, 기준별 평가결과, 결론부의 선행 분석 내용.
- `sample_reference_for_this_section`: 잘 작성된 실제 보고서 예시 중 해당 섹션과 대응되는 구조·문체 참고자료.
- `report_context.draft_date`: 표지 작성 기준 연월 등 보고서 전역 문맥.
- `user_request`: 사용자가 직접 입력한 수정 요청. 다른 입력보다 우선 적용된다.

공통 생성 원칙은 다음과 같다.

- 원본 HWPX 양식의 구조를 훼손하지 않는다.
- 섹션 밖의 내용을 생성하지 않는다.
- 근거 없는 인명, 날짜, 점수, 수행 사실, 성과 수치를 만들지 않는다.
- `추가 정보 필요`, `자료 없음`, `확인 필요` 같은 작업용 안내문을 최종 본문에 남기지 않는다.
- 자료가 부족하면 가능한 근거를 종합하여 보수적 판단 문장으로 쓴다.
- JSON 출력 섹션은 지정된 schema와 key만 반환하고, 코드블록·설명문·Markdown을 포함하지 않는다.
- 본문 출력 섹션은 최종 보고서에 바로 들어갈 문단 또는 지정된 라벨 형식만 반환한다.

## 3. 27개 섹션별 프롬프트 정리

### 1. 표지

- 섹션 ID: `cover`
- 원본 파일: `prompts/Section1_표지.py`
- 핵심 내용: 보고서 표지에 들어갈 사업명, 보고서 제목, 작성 기준 연월, 평가책임자, 평가수행기관 값을 생성한다.
- 참고 자료: 기존 표지 문구 또는 이전 슬롯 값, 프로젝트 기본정보, 보고서 작성 기준일, 사용자 수정요청.
- 생성 기준 및 형식: `project_title`, `report_title`, `report_date`, `evaluation_manager`, `evaluation_institution` 5개 슬롯만 작성한다. 출력은 `section1_cover_slots_v1` JSON 객체이며, 모든 값은 한 줄 문자열이다.
- 기술적 포인트: 표지 전체를 생성하지 않고 HWPX 표지의 고정 슬롯만 생성하여 양식 구조를 보존한다.

### 2. 목차

- 섹션 ID: `toc`
- 원본 파일: `prompts/Section2_목차.py`
- 핵심 내용: 목차 페이지 번호는 LLM이 추정하지 않고 원본 양식 구조를 유지하도록 제어한다.
- 참고 자료: 최종 PDF 변환 후 산출되는 페이지맵 또는 원본 목차 구조.
- 생성 기준 및 형식: `remove_page_notice`와 `page_numbers`만 포함하는 `section2_toc_slots_v1` JSON 객체를 반환한다. 페이지맵이 없으면 페이지 번호는 비워 둔다.
- 기술적 포인트: LLM 추정값 대신 후처리 알고리즘으로 산출된 페이지맵만 사용하게 하여 목차 오류를 방지한다.

### 3. 평가보고서 관련 공지

- 섹션 ID: `notice`
- 원본 파일: `prompts/Section3_공지.py`
- 핵심 내용: 공지 페이지의 placeholder 슬롯 값을 작성한다.
- 참고 자료: 기존 공지 페이지 문구, 프로젝트 기본정보, 평가책임자·수행기관·품질관리 관련 참조문서, 사용자 수정요청.
- 생성 기준 및 형식: 원본 공지 문장 구조는 유지하고 개인명, 검토위원, 품질등급 등 확인되지 않은 값은 `확인 중`으로 처리한다. 출력은 `section3_notice_slots_v1` JSON 객체다.
- 기술적 포인트: 개인정보 또는 미확정 정보를 임의 생성하지 않고, 공식 공지 양식의 변수만 안전하게 채운다.

### 4. 평가등급 결과표

- 섹션 ID: `grade`
- 원본 파일: `prompts/Section4_평가등급_결과표.py`
- 핵심 내용: 평가대상 사업명, 기준별 점수, 질문별 점수, 종합점수, 등급, 산정 이유를 평가등급표 셀에 맞게 생성한다.
- 참고 자료: 기준별 평가점수와 핵심 판단, `grade_score_rows`, 종합 평가정보, 기존 등급표, 사용자 수정요청.
- 생성 기준 및 형식: 시스템 산정 점수를 그대로 사용하고 사유는 90자 이내 한 줄로 작성한다. 산정 이유는 평가질문별 핵심 판단과 근거문서에 기반해야 하며, 각 기준의 종합 사유는 `{기준명} 종합 평가: ...` 형식으로 쓴다. 출력은 `section4_grade_slots_v1` JSON 객체다.
- 기술적 포인트: 점수 산정 로직과 산정 이유 생성 로직을 분리하되, 이유는 기준별 평가질문·핵심 판단에 근거하도록 제한한다.

### 5. 국문 요약

- 섹션 ID: `summary-ko`
- 원본 파일: `prompts/Section5_국문_요약.py`
- 핵심 내용: 평가결과 요약의 사업개요, 평가개요, 성과달성도, 기준별 평가결과, 결론, 환류과제, 교훈을 요약한다.
- 참고 자료: 사업개요, 평가목적과 범위, 평가방법, 성과달성도, 기준별 평가결과, 결론·제언·교훈, RAG 참조자료, 선행 분석 섹션.
- 생성 기준 및 형식: 원본 HWPX의 문단 구조를 유지하기 위해 다수의 요약 슬롯을 JSON으로 반환한다. 각 슬롯은 `가. 사업명 :`, `ㅇ 평가방법:`, `- (문헌조사)` 같은 기존 구조 표지를 포함한다.
- 기술적 포인트: 단일 요약문이 아니라 HWPX 원문 구조에 대응되는 다중 슬롯 요약을 생성하여 원본 양식에 정밀 치환한다.

### 6. 사업 추진배경

- 섹션 ID: `project-background`
- 원본 파일: `prompts/Section6_사업_추진배경.py`
- 핵심 내용: 국가·분야 배경, 협력국 정책, 대상지역 수요, KOICA 전략 부합성, 사업 선정 사유를 작성한다.
- 참고 자료: 사업개요서, 사전조사, PCP, PDM, 국별협력전략, 기준별 평가결과, RAG 참조자료.
- 생성 기준 및 형식: `mdg_maternal_health_context`, `government_policy_context`, `target_region_need`, `koica_policy_alignment`, `project_selection_rationale` 5개 슬롯을 `section6_project_background_slots_v1` JSON으로 반환한다. 모든 슬롯은 `ㅇ `로 시작한다.
- 기술적 포인트: 추진배경을 정책-수요-지역-기관전략-사업선정 논리로 분해하여 근거 기반 배경 문단을 생성한다.

### 7. 사업개요

- 섹션 ID: `project-overview`
- 원본 파일: `prompts/Section7_사업개요.py`
- 핵심 내용: 사업개요 표의 내용 셀을 작성한다.
- 참고 자료: 사업개요서 최종본, 프로젝트 기본정보, RAG 참조자료, 선행 분석 섹션.
- 생성 기준 및 형식: 사업명, 대상국가·지역, 사업기간·예산, 사업분야, 목적, PCP·타당성 검토, 우리정부 분담사항, 파트너 분담사항을 `section7_project_overview_slots_v1` JSON 슬롯으로 반환한다.
- 기술적 포인트: HWPX 표의 행·열·병합 구조를 유지하고 내용 셀만 생성하는 표 기반 슬롯 생성 방식이다.

### 8. 사업설계매트릭스(PDM)

- 섹션 ID: `pdm`
- 원본 파일: `prompts/Section8_PDM.py`
- 핵심 내용: 영향, 성과, 산출물, 활동, 투입, 전제조건의 PDM 표 셀을 작성한다.
- 참고 자료: PDM/ePDM, 사업개요서, 성과지표 실적표, 성과관리 자료, RAG 참조자료.
- 생성 기준 및 형식: `impact_*`, `outcome_*`, `outputs_*`, `activities`, `inputs`, `preconditions` 슬롯을 포함하는 `section8_pdm_slots_v1` JSON 객체를 반환한다.
- 기술적 포인트: 논리모형을 영향-성과-산출-활동-투입-가정 구조로 고정하여 PDM 표의 의미적 일관성을 유지한다.

### 9. 평가의 목적과 범위

- 섹션 ID: `eval-purpose`
- 원본 파일: `prompts/Section9_평가_목적과_범위.py`
- 핵심 내용: 평가 목적, 활용 주체, 평가 대상, 평가 범위, 기준, 기간, 결과 활용 계획을 작성한다.
- 참고 자료: 평가 TOR, 사업개요, 평가범위 관련 자료, 기존 양식, 사용자 수정요청.
- 생성 기준 및 형식: `evaluation_purpose_scope_body` 하나의 슬롯을 포함하는 `section9_eval_purpose_slots_v1` JSON 객체를 반환한다.
- 기술적 포인트: 평가방법 상세는 별도 섹션으로 분리하고, 목적·범위 수준의 문장만 생성하도록 범위를 제한한다.

### 10. 평가매트릭스

- 섹션 ID: `eval-matrix`
- 원본 파일: `prompts/Section10_평가매트릭스.py`
- 핵심 내용: DAC 기준별 평가질문, 판단지표, 자료출처, 평가방법을 매트릭스 표에 맞게 작성한다.
- 참고 자료: 기준별 평가질문, 평가점수, 핵심 근거, 업로드 증빙, 사업개요, PDM, 성과자료.
- 생성 기준 및 형식: 적절성, 일관성, 효과성, 효율성, 지속가능성 기준별로 `question`, `indicator`, `source`, `method` 슬롯을 포함하는 `section10_eval_matrix_slots_v1` JSON 객체를 반환한다.
- 기술적 포인트: 평가기준-질문-지표-자료출처-방법을 하나의 매핑 구조로 생성하여 후속 평가결과 섹션과 연결한다.

### 11. 평가방법

- 섹션 ID: `eval-methods`
- 원본 파일: `prompts/Section11_평가방법.py`
- 핵심 내용: 문헌조사, 정량자료 검토, 이해관계자 면담, 현장확인, 설문 등 평가방법을 작성한다.
- 참고 자료: 평가계획, 인터뷰 기록, 설문 자료, 현장확인 자료, 문헌 목록, 기준별 사용자료와 분석방법, 기존 양식.
- 생성 기준 및 형식: 제공 자료에서 확인되는 방법 중심으로 작성하고, 직접 근거가 약한 방법은 `자료 검토`, `면담자료 확인`, `성과자료 대조`처럼 보수적으로 표현한다. 출력은 최종 보고서 본문 텍스트다.
- 기술적 포인트: 실제 수행 사실을 임의 생성하지 않고, 평가기준·평가질문과 방법론의 기여 관계를 연결해 문장화한다.

### 12. 평가의 한계

## 4. 섹션별 LLM 생성 대상 및 세부 판단 기준

### 4.1 공통 생성 원칙

각 섹션의 LLM 생성 대상은 단순 문장 보완이 아니라, 해당 섹션의 문서 구조와 평가 목적에 맞추어 서로 다른 판단 기준을 적용하는 것이다.

- LLM은 원본 HWPX 양식의 문단, 표, 셀, 슬롯 구조를 유지하면서 빈칸 또는 교체 대상 영역만 생성한다.
- LLM은 시스템이 이미 계산한 점수, 등급, 평균값, 문서 목록, 증빙 공백, 보완조치 등 구조화 데이터를 임의로 재계산하지 않는다.
- LLM은 생성 문장마다 근거가 되는 입력자료를 우선순위에 따라 선택한다. 예를 들어 평가등급 결과표는 `grade_score_rows`와 평가질문별 핵심 판단을 최우선으로 사용하고, 결론부는 15-21번 평가결과와 22번 결론을 우선 사용한다.
- LLM은 이전 보고서의 placeholder, 원본 예시문, 일반론을 그대로 복사하지 않고, 해당 사업의 문서명, 지표명, 산출물명, 이해관계자, 변경 이력, 성과 수준을 반영하여 작성한다.
- LLM은 근거가 없는 경우 확정적으로 쓰지 않고, 확인된 근거와 미확인 한계를 분리하여 표현한다.
- LLM은 사용자가 특정 섹션을 수정한 경우 해당 섹션의 수정본을 기준으로 다시 프롬프트를 실행하여, 후속 섹션에서 이전 버전의 내용이 재사용되지 않도록 한다.

### 4.2 평가등급 결과표의 산정 이유 생성 기준

평가등급 결과표는 단순 점수표가 아니라, 시스템 산정 점수와 평가질문별 핵심 판단을 표 셀에 들어가는 짧은 산정 이유로 변환하는 생성 영역이다. 따라서 LLM은 점수 자체를 생성하지 않고, 왜 그 점수인지에 대한 근거 문장을 생성한다.

#### 4.2.1 공통 산정 이유 문장 구조

각 산정 이유는 다음 네 요소 중 최소 세 요소를 포함해야 한다.

1. 판단 대상: 정책 부합성, 상황변화 대응, 중복 회피, 산출물 달성, 성과 달성, 형평성, 경제성, 운영역량 등 해당 평가질문이 묻는 대상.
2. 근거 문서 또는 근거 내용: CPS, 협력국 정책, 사전조사, PCP, PDM, ToC, 문제나무, 모니터링 보고서, 변경요청서, 회의록, 성과지표 실적표, 예산 집행자료 등.
3. 점수 구간 충족 이유: 4점이면 우수요건까지 충족한 이유, 3점이면 주요 요건은 충족했으나 일부 한계가 있는 이유, 2점이면 일부 근거는 있으나 핵심 요건이 부족한 이유, 1점이면 핵심 요건이 미충족된 이유.
4. 한계 또는 보완 근거: 증빙 공백, 외부요인, 미제출 자료, 성과목표 일부 미달성, 제도화 근거 부족 등 점수를 제한한 사유.

점수별 작성 기준은 다음과 같다.

- 4점: 3점 요건을 충족하고, 추가 우수요건이 근거문서에서 확인되어야 한다. 단순히 "양호" 또는 "부합"만으로는 4점 사유가 될 수 없다.
- 3점: 평가질문이 요구하는 핵심 요건은 전반적으로 충족하나, 참여 수준, 증빙 완결성, 품질, 성과범위, 제도화 등에서 일부 한계가 있을 때 작성한다.
- 2점: 일부 고려 또는 일부 달성은 있으나, 분석방식, 조정근거, 실효성, 증빙, 성과연계가 부족할 때 작성한다.
- 1점: 핵심 요건이 미반영, 미달성, 미대응이거나 성과에 명백한 부정적 영향이 확인될 때 작성한다.

#### 4.2.2 평가질문별 상세 기준

- 적절성 1번, 정책·수요·우선순위 반영 여부
  - LLM은 협력국 국가개발전략 또는 부문별 정책 문서, 한국 정부 또는 KOICA CPS/CAS, 사전조사 및 기초조사, PCP 또는 RD, 최신 PDM, ToC 및 문제나무, 수혜자·이해관계자 수요조사 자료를 함께 확인해야 한다.
  - 4점 산정 이유는 해당 사업이 협력국 정책과 KOICA 전략에 부합할 뿐 아니라, 사전 수요조사와 이해관계자 참여를 통해 문제나무, 변화이론, PDM에 수요와 우선순위가 구체적으로 반영된 경우에만 작성한다.
  - 3점 산정 이유는 정책과 수요에는 전반적으로 부합하지만 현지 참여, 문제분석 방식, 취약계층 수요 반영, PDM 연계 중 일부가 충분히 입증되지 않을 때 작성한다.
  - 2점 또는 1점 산정 이유는 정책명만 언급되어 있거나, 수요조사·우선순위 분석 방식이 부족하거나, 사업 설계와 수요 사이의 연결근거가 불명확할 때 작성한다.
  - 예시 기준: 네팔 모자보건 사업의 경우 네팔 보건전략, KOICA 대네팔 CPS 보건 분야 방향, 사전조사의 모자보건 접근성·보건 인프라 부족 분석, PCP/PDM의 대상지역·수혜자 설정, ToC·문제나무의 원인-해결 논리가 서로 연결되는지 판단한다.

- 적절성 2번, 내·외부 상황변화 대응 여부
  - LLM은 정기 모니터링 보고서, 사업변경 요청서, 운영위원회 또는 JSC 회의록, 리스크 대응 기록, 변경 PDM, 일정·예산 변경 자료를 확인해야 한다.
  - 4점 산정 이유는 코로나19, 정권 교체, 환율·조달 지연, 현장 접근 제한 등 외부 변화가 발생했을 때 사업이 이를 적기에 인지하고 이해관계자와 공유했으며, 실행 가능한 대안을 통해 성과지표 달성 가능성을 유지한 경우에 작성한다.
  - 3점은 대안 마련과 위기 관리가 확인되지만 목표 일부 미달성 또는 증빙 부족이 남는 경우, 2점은 일부 대응했으나 대안의 실효성이 부족한 경우, 1점은 상황변화에 적시 대응하지 못해 성과에 부정적 영향이 큰 경우에 작성한다.

- 일관성 1번, 내적 일관성
  - LLM은 KOICA 타 사업, 국내 기관 사업, 국제규범, SDGs, 인권·젠더·환경 세이프가드, 국내 정책과의 관계를 확인해야 한다.
  - 4점은 중복 없이 역할분담과 시너지가 명확하고 세이프가드 준수가 모범적으로 입증된 경우, 3점은 충돌 없이 대체로 조화되나 구체적 조율 근거가 일부 부족한 경우에 작성한다.

- 일관성 2번, 외적 일관성
  - LLM은 타 공여기관, 수원국 정부, 현지 기관, 민간 주체와의 MoU, 조정회의록, RACI, 유사사업 맵을 확인해야 한다.
  - 4점은 현지 타 주체와 철저히 조율되어 중복 회피와 상호보완적 부가가치가 명확한 경우, 3점은 조율체계는 작동했으나 시너지 근거가 제한적인 경우에 작성한다.

- 효과성 1번, 산출물 달성
  - LLM은 최신 PDM, 산출물 완료보고서, 활동별 결과보고서, 교육·시설·장비 제공 실적, 현장점검 기록을 확인해야 한다.
  - 4점은 계획 산출물이 모두 달성되고 품질 개선 또는 추가 산출이 확인될 때, 3점은 주요 산출물이 대체로 달성되었으나 일부 품질·범위·일정 한계가 있을 때 작성한다.

- 효과성 2번, 성과 및 목표 달성
  - LLM은 기준선·종료선 조사, 성과지표 실적표, 수혜자 만족도, 성과 기여도 분석, 외부요인 검토 자료를 확인해야 한다.
  - 4점은 목표 성과를 모두 달성하고 사업 개입에 따른 변화가 명확할 때, 3점은 성과 달성 가능성과 기여 근거가 대체로 확인되지만 외부요인 구분 또는 일부 지표 한계가 있을 때 작성한다.

- 효과성 3번, 형평성 및 포용성
  - LLM은 성별·지역별·취약계층 분리통계, 소외계층 참여자 명단, 지원 실적, 수혜자 인터뷰와 사례 기록을 확인해야 한다.
  - 4점은 취약계층 포용을 설계·관리하고 추가 포용 효과가 확인될 때, 3점은 균형 있는 성과가 확인되나 일부 분리통계나 참여 증빙이 부족할 때 작성한다.

- 효율성 1번, 경제성 및 시의성
  - LLM은 예산 집행내역, 집행률 분석표, 예산 변경 승인 문서, 단가 비교, 일정표, 조달·계약 문서, 지연 사유와 시정조치 기록을 확인해야 한다.
  - 4점은 예산과 일정이 매우 효율적으로 관리되어 자원 절감 또는 추가 성과가 확인될 때, 3점은 주요 편차가 관리되었으나 일부 지연 또는 예산 조정 한계가 있을 때 작성한다.

- 효율성 2번, 투입·활동·산출의 균형
  - LLM은 인력 투입 계획, 활동별 투입 기록, 주요 활동 간 조정 회의록, 투입 대비 산출 분석표를 확인해야 한다.
  - 4점은 투입·활동·산출 연계가 매우 효율적이고 기대 이상의 운영 효율이 확인될 때, 3점은 전반적으로 균형 있게 조정되었으나 일부 중복·공백 또는 관리 부담이 남을 때 작성한다.

- 지속가능성 1번, 운영역량·재정·위기대응
  - LLM은 운영·유지관리 계획, 지방정부 또는 파트너 예산 확약서, 인수인계 문서, 운영 매뉴얼, 현지 인력 교육 결과, 리스크·위기대응 계획을 확인해야 한다.
  - 4점은 현지 시스템과 조직이 자립역량, 장기 재원, 위기대응능력을 명확히 갖춘 경우, 3점은 운영체계와 역량은 있으나 재원 확약이나 책임체계 일부가 제한적인 경우에 작성한다.

- 지속가능성 2번, 제도적·사회적 환경
  - LLM은 정책·제도 반영 문서, 공식 승인, 지역사회 참여 기록, 역할분담 문서, 사회적 수용성 근거를 확인해야 한다.
  - 4점은 정책·제도·지역사회 기반이 견고하게 구축되어 장기 확산과 제도화 가능성이 높은 경우, 3점은 제도적·사회적 기반은 있으나 실행 근거 또는 책임체계가 일부 부족한 경우에 작성한다.

### 4.3 27개 섹션별 생성 파트 기준

1. 표지
   - LLM 생성 파트: 사업명, 대상국, 기간, 예산, 보고서명, 제출일 등 표지 슬롯.
   - 구체 기준: 프로젝트 메타데이터와 원본 표지의 표기방식을 맞추고, 금액 단위와 기간 표기를 임의 변환하지 않는다.

2. 목차
   - LLM 생성 파트: 원본 양식의 장·절 제목과 목차 항목.
   - 구체 기준: 27개 섹션의 실제 생성 여부와 HWPX 내부 heading 구조를 기준으로 누락·중복 없이 생성한다.

3. 평가보고서 관련 공지
   - LLM 생성 파트: 평가의 독립성, 한계, 책임 범위, 활용 유의사항.
   - 구체 기준: 원본 공지 문구의 법적 성격은 유지하고, 특정 사업의 자료 범위나 평가 수행 조건이 있는 경우 해당 사실만 보강한다.

4. 평가등급 결과표
   - LLM 생성 파트: 기준별·질문별 점수, 종합점수, KOICA 등급, 국무조정실 등급, 산정 이유.
   - 구체 기준: 점수는 시스템 산정값을 유지하고, 산정 이유는 4.2의 평가질문별 상세 기준에 따라 핵심 판단과 근거문서를 연결하여 작성한다. 예를 들어 적절성 1번이 4점이면 CPS, 협력국 정책, 사전조사, PCP, PDM, ToC 또는 문제나무가 수요와 우선순위를 어떻게 반영했는지를 짧게 써야 한다.

5. 국문 요약
   - LLM 생성 파트: 사업 개요, 평가 목적, 주요 평가결과, 결론, 제언의 압축 요약.
   - 구체 기준: 평가등급표와 기준별 평가결과의 점수·판단을 왜곡하지 않고, 높은 점수와 낮은 점수의 이유를 모두 요약한다.

6. 사업 추진배경
   - LLM 생성 파트: 협력국 개발문제, 정책환경, KOICA 개입 필요성, 사업 형성 배경.
   - 구체 기준: 협력국 정책, 통계, 사전조사, 요청서의 문제 인식이 사업목표와 어떻게 연결되는지 설명한다.

7. 사업개요
   - LLM 생성 파트: 사업명, 기간, 예산, 대상지역, 수혜자, 목표, 산출물, 수행체계.
   - 구체 기준: 사업개요서, RD, PDM, 집행계획의 구조화 정보를 표 형태로 정확히 옮기고 추정값을 만들지 않는다.

8. 사업설계매트릭스(PDM)
   - LLM 생성 파트: 상위목표, 사업목표, 산출물, 활동, 지표, 기준선, 목표치, 검증수단, 외부조건.
   - 구체 기준: 최신 승인 PDM을 우선 사용하고, 변경 이력이 있으면 기존 PDM과 변경 PDM의 차이를 반영한다.

9. 평가의 목적과 범위
   - LLM 생성 파트: 평가 목적, 평가대상, 평가기간, 평가범위, 주요 평가질문.
   - 구체 기준: 종료평가 TOR, 평가계획서, 사업기간, 평가대상 구성요소를 기준으로 평가가 무엇을 검증하는지 명확히 쓴다.

10. 평가매트릭스
   - LLM 생성 파트: 평가기준, 평가질문, 판단기준, 지표, 자료원, 자료수집방법.
   - 구체 기준: DAC 6대 기준과 시스템 평가문항을 연결하고, 각 질문에 필요한 증빙 문서를 구체적으로 배치한다.

11. 평가방법
   - LLM 생성 파트: 문헌조사, 면담, 현장조사, 설문, 성과자료 분석 등 방법론 설명.
   - 구체 기준: 실제 사용한 자료군과 방법만 작성한다. 예를 들어 1차 문헌은 KOICA 정책문서·사업자료·PDM·연례보고서·성과점검·종료보고서, 2차 문헌은 협력국 정책·보건통계·지역 배경자료, 3차 문헌은 국제기구·공여국 자료와 경제성·병원경영 참고자료처럼 자료 유형과 목적을 구분한다.

12. 평가의 한계
   - LLM 생성 파트: 자료 미제출, 현장 접근 제한, 표본 한계, 성과기여도 식별 한계, 외부요인.
   - 구체 기준: 증빙 공백과 평가방법의 한계를 구분하고, 한계가 어떤 판단에 영향을 주는지 연결한다.

13. 평가팀 구성 및 시행체계
   - LLM 생성 파트: 평가팀 역할, 수행체계, 협력기관, 조사 일정, 의사소통 구조.
   - 구체 기준: 실제 평가 수행계획과 참여자 역할을 기반으로 쓰며, 미확인 인력·기관은 생성하지 않는다.

14. 성과 달성도
   - LLM 생성 파트: PDM 지표별 목표 대비 실적, 달성률, 증빙, 미달성 사유.
   - 구체 기준: 기준선·목표치·종료선·실적자료를 비교하고, 단순 달성률뿐 아니라 산출물 품질과 성과 연결성을 설명한다.

15. 적절성
   - LLM 생성 파트: 정책·수요 부합성, 설계 적정성, 상황변화 대응, 적절성 점수 판단.
   - 구체 기준: 4.2의 적절성 1번·2번 상세 기준을 본문형 판단으로 확장한다. 특히 정책 부합성은 문서명 나열이 아니라 협력국 정책, KOICA 전략, 수혜자 수요, PDM·ToC 설계가 어떤 논리로 연결되는지 설명해야 한다.

16. 일관성
   - LLM 생성 파트: KOICA·국내 사업과의 내적 일관성, 타 공여·현지 주체와의 외적 일관성.
   - 구체 기준: 유사사업 맵, MoU, 조정회의록, 세이프가드 근거를 사용하여 중복 회피와 상호보완성을 판단한다.

17. 효과성
   - LLM 생성 파트: 산출물 달성, 성과 달성, 사업 기여, 형평성.
   - 구체 기준: PDM, 성과지표, 기준선·종료선, 수혜자 자료를 사용하여 목표 대비 실적과 사업 개입의 기여를 구분한다.

18. 효율성
   - LLM 생성 파트: 예산·일정·조달의 경제성, 투입·활동·산출의 균형.
   - 구체 기준: 예산 집행률, 변경 승인, 지연 사유, 시정조치, 단가 비교, 투입 대비 산출 근거를 사용한다.

19. 지속가능성
   - LLM 생성 파트: 재정·운영 지속가능성, 현지 역량, 위기대응, 제도화, 사회적 수용성.
   - 구체 기준: 운영계획, 예산확약, 인수인계, 교육결과, 정책 반영, 지역사회 참여 근거를 사용하여 편익 유지 가능성을 판단한다.

20. 범분야 이슈
   - LLM 생성 파트: 젠더, 인권, 환경, 취약계층, 사회적 포용 등 범분야 고려사항.
   - 구체 기준: 세이프가드 체크리스트, 분리통계, 취약계층 지원 실적, 현장조사 결과를 기준으로 설계·집행·성과 단계별 반영 여부를 구분한다.

21. 그 외 평가기준
   - LLM 생성 파트: 영향력, 파트너십, 혁신성, 지역특수성 등 추가 기준의 판단.
   - 구체 기준: DAC 6대 기준에 포함되지 않는 추가 평가질문이 있을 때만 생성하고, 해당 질문의 자료원과 판단기준을 명시한다.

22. 결론
   - LLM 생성 파트: 종합 판단, 주요 강점, 주요 한계, 최종 평가의 의미.
   - 구체 기준: 15-21번 평가결과와 평가등급표의 점수 차이를 반영하고, 좋은 점수와 낮은 점수의 원인을 균형 있게 종합한다.

23. 작동요인
   - LLM 생성 파트: 사업 성과에 긍정적으로 기여한 설계·집행·환경 요인.
   - 구체 기준: 높은 점수를 받은 평가질문과 실제 증빙을 연결하여, 재현 가능한 요인만 도출한다.

24. 비작동요인
   - LLM 생성 파트: 성과를 제약한 설계·집행·환경 요인.
   - 구체 기준: 낮은 점수, 증빙 공백, 지연, 외부요인, 운영역량 부족을 구분하고 원인과 영향을 연결한다.

25. 변화이론 분석
   - LLM 생성 파트: 투입-활동-산출-성과-영향의 변화경로, 가정, 외부요인, 경로 수정 필요성.
   - 구체 기준: PDM, ToC, 문제나무, 성과지표 실적을 비교하여 설계 당시 변화논리와 실제 성과경로의 차이를 설명한다.

26. 환류과제
   - LLM 생성 파트: 후속 조치 과제, 담당 주체, 실행 수준, 점검 질문.
   - 구체 기준: 결론과 비작동요인을 실행 가능한 과제로 전환하고, 기관·사업관리·성과관리 단위별로 구체화한다.

27. 교훈
   - LLM 생성 파트: 향후 유사사업에 적용 가능한 일반화된 교훈.
   - 구체 기준: 단순 권고가 아니라 작동요인과 비작동요인에서 반복 적용 가능한 설계·집행·관리 원칙을 추출한다.

## 5. 특허 설명에 반영 가능한 기술 구성 포인트

아래 요소는 특허 명세서의 발명의 구성 또는 효과 설명에 활용할 수 있다.

1. 보고서 양식 기반 섹션 분해
   - 종료평가 보고서의 원본 HWPX 구조를 27개 작성 단위로 고정 식별하고, 각 단위별로 독립 프롬프트와 출력 계약을 적용한다.

2. 섹션별 입력자료 라우팅
   - 동일한 RAG 자료를 전체 프롬프트에 일괄 투입하지 않고, 표지·등급표·PDM·기준별 평가결과·결론·교훈 등 섹션 목적에 따라 참조자료 범위를 달리한다.

3. 구조화 출력과 본문 출력의 혼합 제어
   - 표와 슬롯 기반 영역은 JSON schema를 사용하고, 평가결과·결론부는 최종 보고서 문단을 반환하게 하여 HWPX 자동 치환 정확도를 높인다.

4. 평가점수와 판단근거의 결합
   - 기준별 점수, 평가질문별 핵심 판단, 업로드 증빙, 선행 분석 결과를 결합하여 등급표 산정 이유와 기준별 본문 판단을 생성한다.

5. 선행 섹션 기반 계층형 생성
   - 결론, 작동요인, 비작동요인, 변화이론, 환류과제, 교훈은 앞서 생성된 섹션을 1차 근거로 삼아 중복과 충돌을 줄인다.

6. 환각 억제 및 보수적 문장화
   - 근거 없는 사실은 만들지 않고, 자료가 제한적인 경우에도 작업용 안내문 대신 확인 가능한 범위와 해석 한계를 보고서 문장으로 통합한다.

7. 샘플 보고서 문체 참조와 복사 방지
   - 샘플 보고서는 구조와 문체만 참고하고 고유 문장과 사실은 복사하지 않도록 지시하여, 유사 양식 보고서의 일관성을 유지하면서 표절 위험을 줄인다.

8. HWPX 양식 보존형 자동 작성
   - LLM이 문서 전체를 재생성하지 않고, 원본 HWPX의 표·문단·제목·XML 구조를 유지한 채 필요한 슬롯 또는 본문만 생성하도록 설계한다.

## 6. 특허 명세서용 요약 문장 예시

본 발명은 ODA 사업 종료평가 보고서의 원본 HWPX 양식을 27개의 작성 섹션으로 분할하고, 각 섹션의 목적, 참조 입력자료, 생성 규칙 및 출력 형식을 독립적으로 정의한 섹션별 프롬프트를 적용하여, 프로젝트 기본정보, 평가기준별 점수, 평가질문별 핵심 판단, 업로드 증빙자료, 선행 분석 섹션 및 샘플 보고서 구조를 선택적으로 결합함으로써 원본 양식의 구조를 유지한 상태에서 평가보고서 본문 및 표 셀 값을 자동 생성하는 AI 기반 평가보고서 생성 방법 및 시스템에 관한 것이다.

본 발명은 특히 평가등급 결과표와 기준별 평가결과의 경우 시스템이 산정한 점수와 평가질문별 핵심 판단을 결합하여 산정 이유와 본문 판단을 생성하고, 결론·환류과제·교훈 섹션의 경우 선행 평가분석 결과를 1차 근거로 사용하여 실행 가능한 제언과 후속 점검 질문으로 변환하는 점에서, 단순 문서 요약 또는 범용 보고서 생성과 구별된다.
