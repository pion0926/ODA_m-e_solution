# 종료평가 결과보고서 생성 프롬프트 설계

이 파일은 `평가보고서 작성` 기능의 LLM 작성 전략을 코드와 분리해 관리하기 위한 문서다. 실제 백엔드는 `backend/report_prompts.py`의 동일한 구조화 프롬프트를 사용한다.

## 공통 작성 원칙

- 5-1 종료평가 결과보고서 양식의 장·절 순서를 유지한다.
- 파란 안내문, TIP, 작성 예시, `OOO`, `ㅇㅇ사업` 등 양식 안내용 문구는 최종 산출물에 남기지 않는다.
- 샘플 결과보고서는 문체, 증거 밀도, 평가 논리, 섹션 커버리지를 참고하는 RAG 자료로만 사용한다.
- 자료가 부족해도 빈칸을 두지 않고 확인된 자료와 사업 맥락을 바탕으로 보수적으로 작성한다.
- 점수, 표, 기준별 본문, 결론, 제언의 판단이 서로 맞아야 한다.
- 결론에는 본문에서 다루지 않은 새로운 사실을 넣지 않는다.

## 1. 평가 등급 결과표

필요 자료:
- 사업명, 기간, 예산
- DAC 기준별 세부 질문 점수와 산정 근거
- 업로드 문서별 증빙 요약
- 미확인 항목 목록

입력 파이프라인:
- 기준별 평가 결과에서 점수와 요약을 수집한다.
- 업로드 문서를 기준별 근거자료로 매핑한다.
- 근거가 부족한 세부 질문은 보수적으로 점수를 산정하고 필요한 증빙을 명시한다.

파트 프롬프트:
평가 등급 결과표를 작성한다. 각 DAC 기준의 핵심 질문별 점수는 `/4점` 구조를 유지하고, 산정 이유는 1~2문장으로 구체적 근거와 부족 자료를 함께 적는다.

## 2. 평가결과 요약

필요 자료:
- 사업개요서 또는 ROD
- PDM/ePDM
- 성과지표 목표치와 종료선 자료
- 기준별 평가결과
- 환류과제와 교훈 초안

입력 파이프라인:
- 사업개요, 평가개요, 성과달성도, 기준별 평가결과, 결론과 제언을 압축한다.
- 본문에 없는 새로운 주장을 만들지 않는다.

파트 프롬프트:
KOICA 종료평가 결과보고서의 국문 요약을 작성한다. 사업개요, 평가목적과 범위, 방법, 한계, 성과달성도, DAC 기준별 주요 판단, 결론과 제언을 순서대로 요약한다.

## 3. 대상사업 개요

필요 자료:
- 사업개요서, 기본계획, ROD
- 수원국 정책 및 통계자료
- 대상지역·수혜자 수요 자료
- PDM 또는 성과관리 계획
- 예산 배분, 수행기관, 사업기간 변경 이력

입력 파이프라인:
- 사업명, 기간, 예산, 대상지역, 수혜자, 수행체계를 추출한다.
- PDM의 impact, outcome, output, activity, indicator, MOV, assumption을 구조화한다.

파트 프롬프트:
추진배경은 수원국 개발과제, 정책 부합성, 대상지역 수요, KOICA 지원 논리를 근거 중심으로 서술한다. 사업개요는 표에 들어갈 수 있게 간결히 정리한다.

## 4. 평가개요

필요 자료:
- 평가 TOR 또는 과업지시서
- 평가 질문 및 DAC 기준
- 문헌조사 목록
- 면담자, 설문, 현지조사 계획 및 결과
- 평가팀 구성, 역할, 일정
- 제약사항과 완화조치

입력 파이프라인:
- 기준별 평가질문을 생성한다.
- 질문별 자료원과 방법을 매핑한다.
- 한계는 자료 한계, 접근 제한, 표본 한계, 회상 편향 등으로 분류한다.

파트 프롬프트:
평가 목적과 활용 독자, 평가범위, 기준, 질문, 자료원, 방법, 한계, 품질관리 절차를 전문 평가자가 실제 수행계획을 설명하듯 작성한다.

## 5. 성과달성도 및 변화이론

필요 자료:
- PDM 지표별 기초선, 목표치, 중간선, 종료선
- 성과조사, 모니터링, 최종보고서
- MOV 원자료
- 산출물과 성과 간 인과경로
- 외부요인과 가정 충족 여부

입력 파이프라인:
- PDM 지표를 성과달성도 표 셀에 매핑한다.
- 수치가 있으면 달성률을 계산하고 없으면 필요한 원자료를 명시한다.
- 변화이론은 투입-활동-산출-성과-영향 경로와 끊어진 연결을 설명한다.

파트 프롬프트:
지표별 목표 대비 실적을 표 형식으로 정리하고, 변화이론은 사업이 왜 성과를 냈는지 또는 왜 제약을 받았는지를 작동요인과 비작동요인으로 연결해 분석한다.

## 6. 기준별 평가결과

필요 자료:
- 기준별 배점표
- 문헌, 성과자료, 면담, 설문 근거
- 비교사업, 정책, 국제규범 자료
- 경제성·효율성 자료
- 지속가능성 예산, 제도, 운영 역량 자료

입력 파이프라인:
- 기준별 평가결과와 업로드 문서를 결합한다.
- 각 기준은 평가질문별 판단, 근거, 해석, 한계, 점수 산정 이유 순서로 작성한다.

파트 프롬프트:
DAC 기준별 평가결과를 작성한다. 각 기준은 평가질문별로 `판단-근거-해석-한계-점수 산정 이유`를 포함한다.

## 7. 결론, 교훈, 제언

필요 자료:
- 기준별 평가결과 전체
- 성과달성도와 변화이론 분석
- 운영·관리상 제약
- 이해관계자별 실행 가능 조치
- 후속사업 설계에 반영할 교훈

입력 파이프라인:
- 결론은 본문에서 이미 분석한 내용만 종합한다.
- 작동요인과 비작동요인은 변화이론 및 기준별 평가결과와 연결한다.
- 제언은 관찰사항, 환류과제, 이행부서, 선정사유, 필요자료로 구조화한다.
- 교훈은 후속 사업 체크리스트 질문으로 변환한다.

파트 프롬프트:
결론에는 새로운 사실을 넣지 않고 평가목적과 본문 분석을 종합한다. 제언은 실행 주체와 조치가 분명해야 하며, 교훈은 후속 사업에서 바로 점검 가능한 질문 형태로 변환한다.

## 8. 첨부

필요 자료:
- 영문 요약 작성용 국문 요약
- 출장/원격조사 일정
- 면담자 목록과 질문지
- 설문 원자료와 요약통계
- 참고문헌 목록

입력 파이프라인:
- 본문에 사용된 자료만 참고문헌으로 정리한다.
- 현지조사, 면담, 설문 자료가 없으면 필요한 파일을 명시한다.
- 영문 요약은 국문 요약과 판단이 일치하게 작성한다.

파트 프롬프트:
첨부자료를 실제 제출 가능한 목록 형식으로 정리하고, 자료가 없으면 정확한 추가 필요 자료를 적는다.
